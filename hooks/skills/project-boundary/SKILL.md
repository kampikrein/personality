# Project Boundary Protection — 소프트 가드레일

## 개요

이 프로젝트에는 **프로젝트 경계 보호 체계**가 적용되어 있습니다.
프로젝트 루트(`$CLAUDE_PROJECT_DIR`) 외부의 파일을 수정하거나 삭제하는 행위를 방지합니다.

## 규칙

### 허용
- **프로젝트 내부** 파일의 읽기/쓰기/삭제 — 자유롭게 수행
- **프로젝트 외부** 파일의 **읽기** — 자유롭게 수행 (`cat`, `head`, `Read` 등)
- 프로젝트 내부 경로에 대한 모든 Bash 명령어

### 사용자 확인 필요
- **프로젝트 외부** 파일에 대한 **Write/Edit** 도구 사용
- **프로젝트 외부** 경로를 대상으로 하는 **수정/삭제 Bash 명령어** (`rm`, `mv`, `cp`, `mkdir` 등)
- **프로젝트 외부**로의 출력 리다이렉트 (`>`, `>>`, `tee`)
- 글로벌 패키지 설치 (`npm install -g`, `pip install`)

## 하드 가드레일 (Hook)

`.claude/hooks/` 디렉토리에 두 가지 hook이 등록되어 있습니다:

| Hook | 대상 | 동작 |
|------|------|------|
| `guard-file-boundary.sh` | Write, Edit | `file_path`가 외부면 사용자 확인 요청 |
| `guard-bash-boundary.sh` | Bash | 수정 명령어/리다이렉트/글로벌 설치 감지 시 사용자 확인 요청 |

## 소프트 가드레일 (이 문서)

Hook이 감지할 수 **없는** 복잡한 패턴들이 있습니다. AI는 다음 패턴을 스스로 인식하고 사용자에게 확인해야 합니다:

### Hook이 감지 못하는 위험 패턴
- `bash -c "rm /외부경로"` — 간접 실행
- `xargs rm` — 파이프를 통한 간접 삭제
- `find /외부경로 -exec rm {} \;` — find를 통한 간접 실행
- `eval "rm /외부경로"` — eval을 통한 간접 실행
- `rm $EXTERNAL_PATH` — 환경변수를 통한 외부 경로 참조
- `python -c "import os; os.remove('/외부경로')"` — 스크립트 내 파일 조작
- `node -e "fs.unlinkSync('/외부경로')"` — Node.js를 통한 파일 조작

### AI의 추가 확인 의무
위 패턴을 사용하려 할 때는 **반드시 사용자에게 확인**을 받아야 합니다.
"이 명령어가 프로젝트 외부 파일에 영향을 줄 수 있습니다. 계속할까요?"

## 설계 원칙

1. **Read는 자유**: 외부 파일 읽기는 제한하지 않음 (정보 수집은 안전)
2. **Write는 확인**: 외부 파일 변경은 항상 사용자 확인 필요
3. **이중 보호**: Hook(하드) + AI 인식(소프트)으로 빈틈 최소화
4. **편의 우선**: 프로젝트 내부 작업은 일절 방해하지 않음
