## 0. 설계 전제: 파운더 비전 재해석

파운더가 원하는 것은 단순한 "MBTI 결과 페이지"가 아니다. 사용자가 도착한 순간부터
빠져나가기 어려운 구조를 만드는 것이다.

쇼츠의 중독성은 "끝을 알 수 없는 피드"가 아니다. 핵심은 **각 콘텐츠가 다음 콘텐츠를 예고하는 호기심 갭**이다.
성격 콘텐츠는 이 패턴에 완벽히 부합한다. "나는 왜 이럴까?"라는 질문은 끝이 없기 때문이다.

## 1. 스와이프/쇼츠형 콘텐츠 소비 UX

### 1-1. 패턴 비교 분석

| 패턴 | 강점 | 약점 | 적합도 |
|------|------|------|--------|
| 무한 스크롤 | 구현 간단, 자연스러운 탐색 | 정보 밀도 불균일, 끝 없는 불안감 | 낮음 |
| 카드 스와이프 | 한 번에 하나의 집중, 진행감 | 기술 복잡도 다소 높음 | **높음** |
| 스토리 형태 | 자동 진행, 긴장감 유지 | 사용자 통제권 낮음, 정보 손실 | 중간 |
| 탭 기반 인사이트 | 현재 구현됨, 명확한 구조 | 클릭 장벽, 탐색 낮음 | 낮음 (현재 방식) |

**결론: 카드 스와이프 패턴을 핵심으로 채택.** 성격 콘텐츠는 한 덩어리씩 소화해야 하는 특성상
카드 단위 소비가 가장 적합하다. 각 카드는 "이 사람의 한 면"을 완결적으로 전달한다.

### 1-2. 카드 한 장당 적정 정보량

```
카드 구조 (모바일 기준 375px):
┌─────────────────────────┐
│ [카드 타입 태그]  1/7   │  ← 위치 인식 (지금 어디 있는지)
│                         │
│ [핵심 한 문장]          │  ← 16-20px, 굵게, 2줄 이내
│                         │
│ [설명 텍스트]           │  ← 14px, 3-4줄 이내
│                         │
│ [시각적 요소]           │  ← 스펙트럼 바 OR 아이콘 OR 숫자
│                         │
│ [공감 트리거]           │  ← "이런 사람이라면 공감할 것" 1줄
└─────────────────────────┘
  ← 스와이프 방향 힌트 →
```

**정보량 원칙**: 카드 1장 = 읽는 데 8-12초. 스크롤 없이 한 화면에 완결.
텍스트는 최대 80자 이내 메인 메시지 + 120자 이내 설명.

### 1-3. 카드 시퀀스 설계 (결과 페이지 예시)

```
Card 1: "당신의 첫인상"       ← 흥미 유발 (정체성 확인)
Card 2: "에너지의 방향"        ← 깊이 시작 (내향/외향 스펙트럼)
Card 3: "결정하는 방식"        ← 실용 인사이트
Card 4: "숨겨진 강점"         ← 긍정 감정 극대화
Card 5: "흔히 오해받는 점"     ← 공감 + 안도감
Card 6: "관계에서의 당신"      ← 타인 맥락 (공유 욕구 자극)
Card 7: "지금 당장 시도해볼 것" ← 행동 유도 + 재방문 씨앗
```

**호기심 갭 원칙**: 카드 제목은 결론을 주지 않는다. "당신이 관계에서 하는 실수"가 아니라
"관계에서의 당신"으로. 내용을 보기 전까지 예측 불가능하게 설계한다.

### 1-4. 한국 서비스 참고 사례

**토스 (핀테크 앱)**
- 패턴: 정보 카드를 세로 스크롤로 소비. 각 카드는 완결적 메시지.
- 차용 포인트: 숫자/데이터의 시각적 강조, 카드 간 여백의 리듬감, "더 알아보기" 접기/펼치기.

**카카오뷰**
- 패턴: 에디터 큐레이션 기반 콘텐츠 카드 피드. 썸네일 + 제목의 호기심 유발.
- 차용 포인트: 카드 사이즈 일관성, 주제 태그로 빠른 스캔, 콘텐츠 타입 다양화.

**인스타그램 릴스 / 유튜브 쇼츠**
- 패턴: 수직 스와이프, 화면 전체 점유, 다음 콘텐츠 미리보기.
- 차용 포인트: 화면 전체 사용으로 몰입감 극대화, 다음 카드의 일부가 보이도록 설계.

**잼라이브 / 틱톡**
- 패턴: 참여-예측-확인의 감정 사이클.
- 차용 포인트: "맞았다/틀렸다"의 즉각적 피드백, 공유하고 싶은 순간 설계.

### 1-5. CSS 구현 접근 (Tailwind + Stimulus)

```html
<!-- 카드 컨테이너: CSS scroll-snap 적용 -->
<div class="flex flex-col h-screen overflow-y-scroll snap-y snap-mandatory"
     data-controller="card-feed"
     data-card-feed-current-value="0">

  <!-- 개별 카드: 화면 전체 점유 -->
  <div class="snap-start snap-always flex-shrink-0 h-screen w-full
              flex items-center justify-center px-6"
       data-card-feed-target="card">
    <!-- 카드 내용 -->
  </div>

</div>
```

**핵심 CSS 속성**:
- `scroll-snap-type: y mandatory` — 카드 단위 정렬
- `scroll-snap-align: start` — 각 카드 상단 기준 스냅
- `height: 100dvh` — 모바일 브라우저 주소창 고려 (100vh 대신 dvh 사용)
- `overscroll-behavior: contain` — 부모 스크롤 방지

## 2. 캐릭터 인터랙션 설계

### 2-1. 캐릭터의 역할 정의

파운더의 "웹페이지에서 시선을 끌면서 대화를 나누는 캐릭터"를 해석하면,
이 캐릭터는 단순한 마스코트가 아니다. **사용자의 탐색 여정을 함께하는 동반자**다.

```
역할 계층:
동반자 (Companion)
├─ 가이드: "다음에 이걸 보면 좋겠어" 제안
├─ 공감자: "맞아, 나도 그런 줄 알았는데" 반응
├─ 궁금증 자극자: "근데 왜 그럴까?" 질문
└─ 관계 연결자: "이런 유형이랑 잘 맞더라" 정보
```

동반자 포지셔닝이 중요한 이유: 가이드는 권위적이고, 챗봇은 도구적이다.
동반자는 감정적 연결이 가능하고 재방문 동기가 된다.

### 2-2. 캐릭터 디자인 방향

**Phase 1 추천: 일러스트 기반 감정 표현 캐릭터**

```
디자인 방향:
- 스타일: 2D 일러스트, 토스/카카오프렌즈 중간 지점
  (토스처럼 세련되고, 카카오처럼 친근함)
- 형태: 인간형 but 추상적. 얼굴 특징 최소화.
  감정은 표정보다 자세와 색으로 표현.
- 크기: 화면 하단 고정 (32x32px ~ 64x64px 원형 버블)
  확장 시 대화 카드로 펼쳐짐.
- 색상: 현재 팔레트의 lavender + sage 조합
  (차분하고 신뢰감 있는 톤)
```

**피해야 할 방향**:
- 3D 캐릭터: 로딩 비용, 감정 uncanny valley
- 실제 사람 얼굴: 다양성 문제, 공감대 좁아짐
- 동물 마스코트: MZ세대에게 유치하게 인식될 위험

### 2-3. 대화 인터랙션 패턴

**채택: 말풍선 + 코치형 하이브리드**

```
화면 레이아웃 (모바일):
┌─────────────────────────┐
│                         │
│    [콘텐츠 카드]        │
│                         │
│                         │
│                         │
├─────────────────────────┤
│ [캐] "이 부분 공감돼?"  │  ← 말풍선 (캐릭터 코멘트)
│ ○○  [공감해요] [글쎄]  │  ← 선택지 2개 (탭 타겟 48px+)
└─────────────────────────┘
```

**인터랙션 원칙**:
1. 캐릭터는 먼저 말하지 않는다. 카드를 소비한 후 반응한다.
2. 선택지는 2개로 제한. "예/아니오"보다 감정적 표현 사용.
   ("맞아요, 나도!" / "음, 나는 좀 달라요")
3. 선택에 따라 다음 카드 순서가 미묘하게 달라진다. (개인화 시작)
4. 캐릭터의 코멘트는 짧게. 최대 30자. 호기심 유발 질문형 선호.

### 2-4. Phase 1: 매크로 기반 구현 (현재 스택)

**기술**: Turbo Frames + Stimulus + 서버 사이드 조건 분기

```
구현 범위:
1. 캐릭터 버블 컴포넌트 (Tailwind 애니메이션 + Stimulus)
2. 대화 시나리오 매핑 (YAML or DB 테이블)
3. 사용자 반응 → 다음 카드 선택 로직 (Rails 컨트롤러)
4. 세션 기반 대화 상태 관리 (간단한 상태 머신)
```

**시나리오 구조 예시**:
```yaml
# 카드 3 (결정하는 방식) 이후 캐릭터 반응
trigger: card_3_completed
character_message: "결정할 때 논리가 앞서나요, 감정이 앞서나요?"
options:
  - label: "보통 논리적으로"
    next_card_hint: "analytical"
    response: "그럼 이 다음 카드, 특히 흥미로울 거예요"
  - label: "감정이 먼저예요"
    next_card_hint: "emotional"
    response: "이 부분, 진짜 공감할 것 같은데요"
```

**Stimulus 컨트롤러 설계**:
```javascript
// character_controller.js
// Actions: show(message), respond(option), animate(emotion)
// Targets: bubble, message, options, avatar
// Values: state (idle/active/responding), animating (bool)
```

### 2-5. Phase 2: AI 캐릭터 전환 계획

**전환 조건**: 사용자 인터랙션 데이터 500건 이상 누적 / 서비스 안정화 후

**아키텍처 변화**:
- Phase 1: Rails 컨트롤러 → YAML 시나리오 매핑
- Phase 2: Rails 컨트롤러 → AI API (시스템 프롬프트에 사용자 성향 데이터 주입)

**Phase 2 캐릭터 페르소나 설계 방향**:
```
각 캐릭터는 성격 유형에 연결된 페르소나를 가진다.
사용자는 자신의 유형과 다른 유형의 캐릭터를 통해
"타인을 이해하는 경험"을 얻는다.

예:
- "아리" — 직관적이고 따뜻한 안내자 (F 계열 유형 지향)
- "준" — 분석적이고 명확한 조언자 (T 계열 유형 지향)
```

**character.ai 참고 포인트**:
- 각 캐릭터가 유저 이전 대화를 "기억"하는 것처럼 느껴짐
- Phase 1에서는 세션 스토리지에 대화 이력 저장으로 유사 효과 구현 가능

## 3. 감정 흐름 기반 리텐션 설계

### 3-1. 확장된 감정 여정 맵

```
호기심       몰입        발견         성찰         공유         재탐색
(Curiosity) (Immersion) (Discovery) (Reflection) (Sharing)   (Return)
    │            │           │           │           │           │
    ▼            ▼           ▼           ▼           ▼           ▼
"나는 어떤  "다음 질문  "맞아, 이게  "나한테     "친구도     "더 깊이
 사람일까?" 이 궁금해"  진짜 나야"   왜 그럴까"  궁금할 듯"  알고 싶어"
    │            │           │           │           │           │
랜딩/진입    검사 중     결과 첫 화면  인사이트    공유 기능   다음 콘텐츠
```

### 3-2. 감정 단계별 UI 패턴

**호기심 단계 (랜딩/진입)**
- 색상: 따뜻한 중립 톤 (현재 cream/sand 계열 유지)
- 모션: 부드러운 fade-in, 캐릭터 첫 등장 애니메이션 (250ms ease-out)
- 타이포그래피: 질문형 헤드라인 (24px+, 굵게), 첫 문장이 전부
- 핵심 패턴: 화면에 "한 가지 질문만" 존재. 선택지 과부하 금지.

**몰입 단계 (검사 중)**
- 색상: 점진적 색상 변화. 문항이 진행될수록 배경이 약간 깊어짐.
- 모션: 질문 전환 시 수평 슬라이드 (Turbo Frame 활용). 200ms.
- 타이포그래피: 질문은 크게 (18px), 선택지는 작게. 위계 명확.
- 진행 표시: 상단 얇은 프로그레스 바. 퍼센트 숫자 없이 시각적으로만.
- 핵심 패턴: 이탈을 유발하는 요소 0. 네비게이션 바도 숨김.

**발견 단계 (결과 도출)**
- 색상: 밝고 선명하게 전환. 결과 타입의 고유 색상 강조.
- 모션: 결과 페이지 진입 시 2-3초 "계산 중" 애니메이션 (흥분 빌드업).
  이후 카드 1번 fade-in. 나머지 카드는 스와이프 대기.
- 타이포그래피: 유형 이름 36px+, 화면 중앙. "이게 나야"의 임팩트.
- 핵심 패턴: 첫 결과 화면은 복잡하지 않게. 한 문장 + 시각적 요소만.

**성찰 단계 (인사이트)**
- 색상: 차분하고 깊은 톤으로 전환. lavender/sage 계열 배경.
- 모션: 카드 스와이프는 부드럽게 (300ms cubic-bezier). 서두르지 않는 리듬.
- 타이포그래피: 본문 가독성 최대화. 16px, line-height 1.7.
- 핵심 패턴: 각 인사이트 카드 하단에 캐릭터 반응. 사용자 선택 유도.

**공유 단계**
- 색상: 브랜드 원색으로 강조. 공유 버튼만 high contrast.
- 모션: 공유 카드 생성 시 생성 애니메이션 (300ms). 완성감.
- 핵심 패턴: 공유할 "한 장짜리 카드" 제공. 텍스트가 아닌 이미지.
  "나 이런 사람" 공유 = 자기표현 + 서비스 홍보.

**재탐색 단계 (세션 종료 시)**
- 색상: 세션 종료 화면은 부드럽고 따뜻하게.
- 핵심 패턴: "다음에 볼 것" 3개 제안. 지금 바로 보기 + 나중에 알림.
  알림 허용 유도 (앱 아이콘 추가 or 브라우저 알림).

### 3-3. "한 번 더 보고 싶은" 감정 트리거 설계

**트리거 1: 미완성 공개 (Zeigarnik Effect)**
- 인사이트 카드 중 마지막 2장은 "잠금" 표시. 회원가입 후 해제.
- 또는: "관계 유형 분석"은 상대방 유형 선택 후에 공개.

**트리거 2: 비교 욕구 자극**
- "같은 유형 사람들 중 42%는 이 강점을 인식하지 못해요"
- 숫자 + 집단 비교는 자기 위치 확인 욕구를 자극.

**트리거 3: 예고 카드**
- 마지막 카드에: "다음에 확인할 것: [오늘의 관계 패턴 분석]"
- 내일 다시 오게 하는 명분 제공.

**트리거 4: 공감 검증**
- 카드 하단에 "이 내용이 자신에 맞나요?" 1-5 슬라이더.
- 응답하면 "같은 유형의 89%가 공감했어요" 즉시 표시.
- 집단 소속감 + 참여 완결감.

### 3-4. 세션 종료 UX

세션 종료 화면 구조:
┌─────────────────────────┐
│ "오늘 탐색한 내용"      │
│                         │
│ ✓ 에너지 유형           │

## 4. 진입점 다양화 UX

### 4-1. 현재 구조의 한계

현재: 랜딩 → 성격검사 → 결과 (단일 퍼널)

파운더 비전: "꼭 성격검사가 메인 페이지일 필요는 없을 거야"

### 4-2. 5개 진입점 설계

**진입점 A: 성격검사 (현재 경로)**
- 대상: "MBTI 결과 확인하고 싶다"
- 랜딩 메시지: "당신은 어떤 사람인가요? 10분으로 알아보세요."
- 퍼널: 랜딩 → 검사 → 결과 → 인사이트 피드

**진입점 B: 고민 상담**
- 대상: "지금 뭔가 답답한데 이유를 모르겠다"
- 랜딩 메시지: "지금 어떤 상황인지 말해줘. 성격에서 답을 찾을 수 있어."
- 퍼널: 고민 선택 (카드 4-5개) → 관련 인사이트 선공개 → 검사로 유도
- 예시 고민 카드: "자꾸 남의 시선이 신경 쓰여요", "결정을 못 내리겠어요", "혼자인 게 편한데 외롭기도 해요"

**진입점 C: 관계 질문**
- 대상: "친구/연인/동료랑 왜 이렇게 잘 안 맞는지 알고 싶다"
- 랜딩 메시지: "저 사람이 왜 그럴까요? 성격 유형으로 이해해보기"
- 퍼널: 상대방 유형 선택 → 관계 패턴 인사이트 → 내 유형 검사 유도

**진입점 D: 오늘의 인사이트 (SNS 유입)**
- 대상: SNS에서 "공감 가는 성격 콘텐츠" 보고 클릭
- 랜딩: 해당 콘텐츠 카드 전체 공개 → 하단에 "나도 알아보기" CTA
- 퍼널: 콘텐츠 소비 → 관련 카드 2-3개 더 보기 → 검사 유도

**진입점 E: 직업/강점 탐색**
- 대상: "내 강점이 뭔지 모르겠다", "진로 결정이 어렵다"
- 랜딩: "당신의 성격적 강점을 5분 만에 발견하세요"
- 퍼널: 강점 중심 5문항 → 강점 카드 → 심층 검사 유도

### 4-3. SNS/검색 유입 랜딩 경험

```
유입 경로별 첫 화면 최적화:

인스타그램/틱톡 유입:
- 유입한 콘텐츠를 전체화면 카드로 즉시 표시
- 스와이프 유도 힌트 (하단 여백 + 다음 카드 살짝 보임)
- 브랜드 로고는 작게, 콘텐츠가 주인공

카카오톡 공유 유입:
- 공유한 사람의 유형 힌트 포함 ("OO 유형인 친구가 공유했어요")
- "나도 내 유형 알아보기" CTA 강조

구글 검색 유입 (MBTI 관련):
- 검색 의도에 맞는 콘텐츠 즉시 노출 (SEO 최적화 필요)
- 롱폼 콘텐츠 + 검사 CTA 하단 배치
```

## 5. 기술 실현 가능성 (현재 스택)

### 5-1. Hotwire/Turbo + Stimulus 구현 가능 범위

| 기능 | 구현 방법 | 난이도 | Phase |
|------|-----------|--------|-------|
| 카드 스와이프 피드 | CSS scroll-snap + Stimulus (상태 추적) | 중 | 1 |
| 카드 진행 표시기 | Stimulus target + counter | 하 | 1 |
| 캐릭터 말풍선 | Turbo Frame + Stimulus (show/hide) | 하 | 1 |
| 대화 선택지 응답 | Turbo Stream + 서버 조건 분기 | 중 | 1 |
| 인사이트 잠금/해제 | Rails 세션 + Turbo Frame | 중 | 1 |
| 공유 이미지 생성 | puppeteer/wkhtmltopdf 서버 렌더링 | 고 | 2 |
| 개인화 카드 순서 | Rails 세션 + 점수 벡터 기반 정렬 | 중 | 2 |
| AI 캐릭터 대화 | Turbo Stream + AI API 스트리밍 | 고 | 3 |
| 알림 (재방문) | Web Push API + Service Worker | 고 | 3 |

### 5-2. 현재 스택의 한계 및 보완 방안

**한계 1: 부드러운 스와이프 모션**
- Turbo 기본 전환은 스와이프 제스처를 지원하지 않음
- 보완: CSS scroll-snap은 순수 CSS. Turbo 없이 가능.
  Stimulus에서 touch 이벤트 추가 감지로 스와이프 완성.

**한계 2: 실시간 캐릭터 반응**
- 서버 요청-응답 구조라 즉각적 반응이 어려울 수 있음
- 보완: 캐릭터 반응은 대부분 클라이언트 사이드에서 처리.
  Stimulus 컨트롤러에서 로컬 시나리오 매핑 JSON 사전 로드.

**한계 3: 공유 이미지**
- HTML을 이미지로 변환하는 기능이 Rails 기본 스택에 없음
- 보완 단기: 텍스트 기반 공유 (카카오 링크 커스텀 OG 이미지 활용)
- 보완 중기: Cloudinary나 imgix API로 서버 사이드 이미지 생성

### 5-3. 모바일 웹 최적화 필수 체크리스트

```
접근성:
☐ 스와이프는 반드시 키보드 화살표 대안 제공
☐ 캐릭터 말풍선: aria-live="polite" 적용
☐ 카드 전환 시 포커스 이동 관리 (Stimulus에서 처리)
☐ @media (prefers-reduced-motion) 적용 (스와이프 애니메이션 비활성)

성능:
☐ 카드 이미지/애니메이션 lazy load
☐ 캐릭터 SVG 인라인 처리 (HTTP 요청 최소화)
☐ 카드 콘텐츠는 첫 3장만 즉시 로드, 나머지 prefetch

터치:
☐ 버튼 최소 44x44px (현재 코드베이스 확인 필요)
☐ 스와이프와 스크롤 충돌 방지 (touch-action: pan-y)
☐ 탭 딜레이 제거 (touch-action: manipulation)

레이아웃:
☐ 100dvh 사용 (모바일 주소창 대응)
☐ safe-area-inset 적용 (노치 있는 기기 대응)
☐ 가로 스크롤 없음 확인
```
