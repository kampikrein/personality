# 프로젝트 컨텍스트 정합성 분석

## Summary

personality 프로젝트의 기획 문서 5건, 코드점검 문서 6건, 코드베이스 분석 문서 4건, 실제 코드(14모델, 19서비스, 8컨트롤러)를 정독하여 5개 에이전트의 역할을 MVP 구성요소별로 매핑하고, 순차/병렬/갈등해소 협업 시나리오를 도출했다. 현재 코드베이스는 MVP의 기반 구조(모델, 스키마, 서비스 레이어, 뷰)가 대부분 구현되어 있으나, 콘텐츠 레이어(독자적 문항 설계, 유형 해석 텍스트, 인사이트 내용)가 미완성이며, 이것이 자문 에이전트(심리학, MBTI, 애니어그램)의 핵심 기여 영역이다.

## Details

### 1. 기존 기획 문서 분석

#### 1-1. 프로젝트 철학 (004) 핵심 가치관

| 가치 | 설명 |
|------|------|
| 자기 이해 | "한 사람에게는 하나의 성격" — 성격 유형을 통한 자기 인식 여정 |
| 타인 수용 | 타인을 이해하고 자신을 수용하는 자유 추구 |
| 저작권 우회 | 법적 리스크를 미리 최소화하되 기존 서비스와 차별화 |
| 고급화 전략 | 대중 모객 후 고급 성격 서비스로 전환 |
| 확장성 | 타로/사주 등 운명 서비스로의 확장 가능성 |

#### 1-2. 저작권 조사 (002, 003) 핵심 결론

**MBTI 법적 위험:**
- "MBTI", "Myers-Briggs" 등 명칭은 등록 상표 — 서비스명/마케팅에 직접 사용 불가
- 검사 문항 93개+ 는 저작권 보호 대상 — 복제/변형 금지
- 4글자 유형 코드(INTJ 등) 자체는 보호 대상 외(짧은 문자 조합)
- E/I, S/N, T/F, J/P 이론적 분류 체계는 공공 영역(카를 융 이론)
- 한국 부정경쟁방지법: 공식 브랜드의 "명성 편승"도 위반 소지

**애니어그램 법적 위험:**
- Arica v. Palmer 판례: 9유형 구조는 공공 영역(저작권 보호 외)
- 단, 특정 기관의 검사지(KEPTI 등)는 개별 저작물로 보호
- 독자적 문항/해석/보고서를 만들면 자유롭게 사용 가능

**핵심 전략 (16Personalities 모델):**
1. 상표 회피: "MBTI" 대신 독자 브랜드명 사용
2. 저작권 회피: 공식 문항이 아닌 독자 문항 개발
3. 이론 차용: E/I, S/N, T/F, J/P 분류 체계(공공 영역) 활용
4. 독자 요소 추가: 기존 체계와 구별되는 자체 척도/라벨

#### 1-3. 법률우선 MVP 설계 (005) 구성요소 정리

| 구성요소 | 핵심 기능 | 현재 구현 상태 |
|----------|----------|--------------|
| **A. 문항 엔진** | 도메인 기반 문항 뱅크(에너지/의사결정/관계/회복), 버전 관리, 리커트형 1-5, 품질 점검 | **구현됨** — QuestionSet/Question 모델, 4도메인 x 5문항 = 20문항 시드, 버전 관리(activate!) |
| **B. 점수 엔진** | 0-100 정규화, 신뢰도 보정, 프로필 벡터 저장, 정책 차단 | **구현됨** — Scoring 모듈 5개 서비스(DomainCalculator→Normalizer→TypeClassifier→ReliabilityAdjuster→PolicyChecker) |
| **C. 프로필 컴포저** | 점수→프로필 카드 변환, 독자 네이밍, 콘텐츠 톤 정책 | **구현됨** — Profiles::Composer, ToneFilter, TypeContentService, PersonalityType 16개 마스터 데이터(독자적 캐릭터명) |
| **D. 인사이트 모듈** | 5개 맥락(협업/갈등/학습/커리어/회복), 규칙+템플릿, 설명 블록 | **구현됨** — Insights 모듈 7개 서비스(ContextEngine + 5개 모듈 + ExplanationBuilder) |
| **E. 신뢰/컴플라이언스** | 최소 개인정보, 익명 옵션, 데이터 수명주기, 정책 필터 | **구현됨** — Compliance 3개 서비스, Consent/DeletionRequest/AuditLog/Alert 모델, 익명 세션 기반 |
| **F. 품질 운영** | 대시보드, 경보, 배포 게이트 | **부분 구현** — Admin 대시보드/알림 컨트롤러 존재, Quality::BotDetector/SpeedAnalyzer 존재. 일부 뷰 누락 |

### 2. 코드베이스 현황 분석

#### 2-1. 구현 완료된 것

| 영역 | 상세 |
|------|------|
| **모델 레이어** | 14개 모델(+ApplicationRecord), 관계/검증/콜백/스코프 정의 완료 |
| **DB 스키마** | 14테이블, 유니크 인덱스 10개, 외래키 14개, JSON 컬럼 활용 |
| **서비스 레이어** | 5개 도메인(Scoring/Insights/Profiles/Quality/Compliance), 19개 서비스 클래스 |
| **컨트롤러** | 사용자 플로우 7개 + Admin 5개 = 12개 컨트롤러 |
| **뷰** | 사용자 플로우 전체(랜딩→질문→결과), Turbo Frame, Tailwind CSS |
| **JS** | Stimulus 8개 컨트롤러(리커트 UI, 자동저장, 진행률, 스펙트럼 바, 타입 공개 애니메이션) |
| **인증** | 익명 세션 기반(AnonymousSession) + 선택적 User 등록 + Admin HTTP Basic Auth |
| **배포** | Kamal + Docker + Thruster, CI 파이프라인(Brakeman/bundler-audit/RuboCop) |

#### 2-2. 미구현 또는 개선 필요 사항

| 영역 | 상세 | 관련 에이전트 |
|------|------|-------------|
| **문항 콘텐츠 확장** | 현재 20문항(4도메인 x 5). MVP 목표에 비해 문항 수 부족. 학술적 근거 있는 문항 설계 필요 | 심리학, MBTI, 애니어그램 |
| **유형 해석 텍스트 고도화** | PersonalityType의 character_name, summary, strengths 등이 seeds.rb에 있으나 학술적 검증 미수행 | 심리학, MBTI, 애니어그램 |
| **인사이트 콘텐츠 검증** | 5개 모듈(협업/갈등/학습/커리어/회복)의 규칙+템플릿이 코드로 존재하나 심리학적 타당성 미검증 | 심리학, MBTI, 애니어그램 |
| **테스트 커버리지** | 19개 서비스 중 12개 미테스트 (ReliabilityAdjuster, DeletionProcessor, Insights 전체, Profiles 전체, Quality 전체) | 코딩 |
| **CI에 RSpec 누락** | config/ci.rb에 테스트 실행 스텝 없음 | 코딩 |
| **프론트엔드 고도화** | 결과 페이지 UI/UX 개선, 모바일 최적화, 애니메이션 완성(2개 Stimulus 컨트롤러 스텁) | UI/UX |
| **콘텐츠 톤 정책** | ToneFilter 존재하나 실제 정책 규칙의 심리학적 검토 미수행 | 심리학 |

#### 3-2. 에이전트별 역할 요약

**심리학 전문가 — "이론적 토대와 윤리적 감시"**
- 모든 구성요소의 학술적 근거 제공 및 윤리 검토
- 문항 설계 원칙(구성 타당도, 내용 타당도), 점수 해석 기준
- 콘텐츠 톤 정책의 심리학적 검토(낙인 금지, 결정론 금지, 행동 지향)
- 핵심 산출물: 문항 설계 가이드라인, 프로필 해석 가이드, 윤리 체크리스트

**MBTI 전문가 — "한국형 MBTI 트렌드와 독자 콘텐츠"**
- 4차원(E/I, S/N, T/F, J/P) 기반 문항 초안 작성
- 16유형별 독자적 캐릭터명/설명/조언 콘텐츠 작성 (공식 MBTI 표현 회피)
- 한국 MZ 세대의 MBTI 문화 트렌드 반영
- 핵심 산출물: 독자 문항 세트, 유형별 콘텐츠 시트, 한국어 톤 가이드

**애니어그램 전문가 — "성장 역동과 심화 해석"**
- 9유형 기반 문항 설계(핵심 동기, 두려움, 스트레스 반응)
- 날개(wing), 통합/분열 방향 등 심화 해석 콘텐츠
- 성장 방향 인사이트(Recovery Module, Learning Module 콘텐츠)
- 핵심 산출물: 애니어그램 문항 세트, 유형별 성장 인사이트, 통합 해석 가이드

**코딩 전문가 — "Rails 백엔드 구현과 품질 보증"**
- 19개 서비스의 구현/유지보수/테스트
- DB 스키마 관리, 마이그레이션, 인덱스 최적화
- CI/CD 파이프라인, 보안 도구(Brakeman, bundler-audit)
- 핵심 산출물: 코드, 테스트, 마이그레이션, API

**UI/UX 전문가 — "사용자 경험과 시각 디자인"**
- Tailwind CSS + Stimulus.js 기반 프론트엔드
- 리커트 선택 UI, 결과 페이지 프로필 카드, 스펙트럼 바
- 모바일 반응형, 접근성, 한국어 타이포그래피(Pretendard)
- 핵심 산출물: ERB 뷰, Stimulus 컨트롤러, CSS, 디자인 시스템

### 4. 에이전트 협업 시나리오

#### 4-1. 순차 워크플로우 (기능 개발 시)

```
Phase 1: 이론 설계
  심리학 전문가
    → 입력: MVP 구성요소 요구사항
    → 출력: 문항 설계 원칙, 점수 체계 이론, 윤리 가이드라인
    → 체크포인트: 학술 근거 문서 리뷰

Phase 2: 콘텐츠 작성 (병렬)
  MBTI 전문가                    애니어그램 전문가
    → 입력: Phase 1 가이드라인      → 입력: Phase 1 가이드라인
    → 출력: MBTI 기반 문항/콘텐츠    → 출력: 애니어그램 기반 문항/콘텐츠
    → 체크포인트: 법적 경계 준수 확인  → 체크포인트: 법적 경계 준수 확인

Phase 3: 구현 (병렬)
  코딩 전문가                     UI/UX 전문가
    → 입력: Phase 2 콘텐츠         → 입력: Phase 2 콘텐츠 + 디자인 요구사항
    → 출력: 서비스/모델/테스트 코드   → 출력: 뷰/Stimulus/CSS
    → 체크포인트: 테스트 통과, CI 녹색 → 체크포인트: 크로스 브라우저, 모바일 확인

Phase 4: 검증
  심리학 전문가: 최종 산출물의 윤리/정확성 리뷰
    → 입력: 구현된 기능의 실제 동작 결과
    → 출력: 승인 또는 수정 요청
```

#### 4-2. 병렬 리뷰 시나리오

동일 기능을 다른 관점에서 동시 리뷰하는 패턴:

**예: 새로운 유형 설명 콘텐츠 검토**
- 심리학 전문가: "이 설명이 학술적으로 정확한가? 과잉 일반화는 없는가?"
- MBTI 전문가: "한국 사용자가 공감할 수 있는 표현인가? 트렌드에 맞는가?"
- 애니어그램 전문가: "성장 방향 제안이 애니어그램 이론과 정합하는가?"
- 코딩 전문가: "ToneFilter 정책에 위반되는 표현이 있는가? RestrictedTerms에 걸리는가?"
- UI/UX 전문가: "텍스트 길이가 카드 UI에 적합한가? 모바일에서 읽기 편한가?"

#### 4-3. 갈등 해소 패턴

**갈등 유형 1: 학술 정확성 vs 대중 접근성**
- 상황: 심리학 전문가가 "이 표현은 학술적으로 부정확하다"고 지적, MBTI 전문가가 "한국 사용자들은 이 표현을 더 잘 이해한다"고 반론
- 해결: 프로젝트 철학의 우선순위 적용
  1. 법적 경계 원칙 위반 여부 (최우선)
  2. 윤리 원칙 위반 여부 (낙인 금지, 결정론 금지)
  3. 위 두 가지를 위반하지 않는다면, 대중 접근성 우선 (프로젝트 목표: 자기 이해를 위한 서비스)
  4. "참고용 인사이트, 진단이 아님" 고지로 학술적 한계를 투명하게 명시

**갈등 유형 2: MBTI 관점 vs 애니어그램 관점**
- 상황: 점수 체계나 유형 분류에서 두 체계의 기준이 충돌
- 해결: MVP에서는 독립 영역으로 분리
  1. 도메인 설계상 이미 분리됨 (energy/decision_making/relationship/recovery)
  2. 향후 통합 해석(MBTI + 애니어그램 크로스 분석)은 심리학 전문가가 중재
  3. Question.domain 레벨에서 어떤 체계의 문항인지 구분 가능

**갈등 유형 3: 콘텐츠 품질 vs 개발 속도**
- 상황: 자문 에이전트가 콘텐츠 개선을 요구하나 구현 에이전트의 공수 증가
- 해결: MVP 경계 기준 적용
  1. "법적 경계 원칙"과 "윤리 원칙" 위반은 반드시 수정 (비협상)
  2. 콘텐츠 품질 향상은 Wave 2/3로 분류 가능
  3. 8주 로드맵의 각 주차 목표에 맞춰 우선순위 조정

### 5. 에이전트 프롬프트에 포함할 프로젝트 컨텍스트 체크리스트

#### 5-1. 모든 에이전트 공통

- [ ] **프로젝트 철학**: 자기 이해, 타인 수용, 자유 추구
- [ ] **법적 경계 원칙**:
  - 공식 MBTI/애니어그램 검사 문항, 보고서 문구, 보호된 브랜드 표현 미사용
  - 독자적 문항 뱅크, 독자적 척도 라벨, 독자적 보고서 문구 사용
  - "참고용 인사이트, 진단이 아님" 고지 유지
- [ ] **콘텐츠 톤 정책**: 낙인 금지, 결정론적 주장 금지, 행동 지향 문구
- [ ] **제품 포지셔닝**: 임상 진단 아님, 자기이해 및 관계 인사이트 서비스
- [ ] **도메인 구조**: energy(E/I), decision_making(S/N), relationship(F/T), recovery(J/P)
- [ ] **문서 체계**: `docs/` 디렉토리의 기존 문서 참조 경로

#### 5-2. 자문 에이전트 추가 (심리학, MBTI, 애니어그램)

- [ ] **MVP 구성요소 이해**: 문항 엔진, 점수 엔진, 프로필 컴포저, 인사이트 모듈, 신뢰/컴플라이언스
- [ ] **현재 구현 현황**: 19개 서비스 구현됨, 20문항 시드 존재, 16유형 마스터 데이터 존재
- [ ] **저작권 핵심 결론**:
  - MBTI: 명칭 상표, 문항 저작권, 이론 체계(융)는 공공 영역
  - 애니어그램: 9유형 구조 공공 영역, 특정 검사지는 개별 저작물
  - 부정경쟁방지법: 공식 브랜드 명성 편승 금지
- [ ] **콘텐츠 요구사항**: 독자적 캐릭터명(공식 MBTI 명칭과 무관), 한국어 우선, 행동 지향
- [ ] **산출물 형식**: 마크다운 문서, JSON 구조(strengths/caution_patterns 등)

#### 5-3. 구현 에이전트 추가 (코딩, UI/UX)

- [ ] **기술 스택**: Ruby 3.3.10 / Rails 8.1.2 / PostgreSQL(production) / SQLite(dev)

## Key Findings

- **콘텐츠 갭이 가장 큰 병목**: 기술 인프라(모델, 서비스, 뷰)는 대부분 구현되어 있으나, 학술적 근거 있는 문항과 유형 해석 콘텐츠가 부족하다. 이것이 자문 에이전트 3인의 핵심 기여 영역이다.

- **법적 경계가 모든 에이전트의 최우선 제약조건**: 5개 에이전트 모두가 법적 경계 원칙을 이해하고 자기 영역에서 준수해야 한다. 특히 MBTI 전문가는 상표/문항 저작권 회피를, 애니어그램 전문가는 특정 검사지 미사용을 항상 검증해야 한다.

- **자문-구현 비대칭 구조**: 심리학/MBTI/애니어그램 전문가는 "콘텐츠와 가이드라인"을 산출하고, 코딩/UI/UX 전문가는 이를 "코드와 화면"으로 구현하는 비대칭 관계다. 자문 에이전트의 산출물 형식(마크다운, JSON 구조)이 구현 에이전트의 입력으로 직결되므로, 산출물 템플릿 표준화가 중요하다.

- **테스트 커버리지 갭**: 19개 서비스 중 12개(63%)가 테스트 미작성. 특히 Insights 전체(7개)와 Profiles 전체(3개)에 테스트가 없어, 콘텐츠 변경 시 회귀 검증이 불가하다.

- **CI에 RSpec 누락**: 보안/스타일 검사만 CI에 포함. 테스트 실행이 자동화되지 않은 상태다.

- **4도메인 구조가 에이전트 협업의 자연스러운 분할 경계**: energy(E/I), decision_making(S/N), relationship(F/T), recovery(J/P) 4개 도메인이 MBTI 4차원과 대응하면서도 독자적 라벨을 사용한다. 애니어그램 통합은 향후 추가 도메인 또는 기존 도메인의 확장으로 설계 가능하다.

## Recommendations

1. **자문 에이전트 산출물 템플릿 표준화**: 심리학/MBTI/애니어그램 전문가의 산출물이 코딩/UI/UX 전문가의 입력으로 직접 사용될 수 있도록, JSON 구조(strengths: [], caution_patterns: [], 등)와 마크다운 형식의 표준 템플릿을 정의한다.

2. **문항 확장 우선 착수**: 현재 20문항(도메인당 5개)은 통계적 신뢰도 확보에 부족하다. 심리학 전문가의 가이드라인 아래 MBTI/애니어그램 전문가가 각 도메인 10-15문항을 목표로 확장하고, 코딩 전문가가 qset_v2로 시드 데이터를 추가한다.

3. **테스트 커버리지 확보**: 코딩 전문가가 미테스트 12개 서비스의 테스트를 작성하고 CI에 RSpec 실행 스텝을 추가한다. 특히 ReliabilityAdjuster(Pearson 상관계수)와 DeletionProcessor(GDPR 삭제)가 최우선이다.

4. **법적 경계 자동 검증 도구 강화**: RestrictedTerms 서비스에 "MBTI", "Myers-Briggs", "마이어스-브릭스" 등 등록 상표와 공식 문항 표현의 자동 탐지 규칙을 추가한다.

5. **에이전트 간 갈등 해소 프로토콜 문서화**: 학술 정확성 vs 대중 접근성, MBTI vs 애니어그램 관점 충돌 시의 의사결정 기준을 `.claude/` 설정에 명시하여 모든 에이전트가 동일한 우선순위 기준을 따르도록 한다.
