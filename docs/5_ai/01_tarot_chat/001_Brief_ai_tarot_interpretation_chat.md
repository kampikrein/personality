# AI 타로 해석 채팅 — 사전 연구 Brief

## Intent

personality 타로 셔플 앱에 **AI 기반 타로 해석 채팅 기능**을 구현하기 위한 **사전 연구** 방향을 정의한다.

**핵심 경험**: 유저가 카드를 뽑으면 AI가 해당 카드를 해석해주고 의미를 해설하되, 단순 카드 의미 나열이 아니라 유저의 정보(경험 수준, 질문, 성격 프로필), 카드의 특성(아케타입, 정/역위치, 수트), 덱의 특성(RWS, 마르세유 등 해석 전통), 사조별 해석 관점(심리학적, 영적, 상징학적)을 종합하여 **개인화된 해석 경험**을 전달하는 것.

**출력 형태**: 텍스트 채팅(기본) → 구조화된 리포트 → 음성 해설(TTS/보이스) → 이미지/영상으로 감각적 경험까지 확장.

**연구 필요 영역**:
1. 기술 구현 — LLM API 연동, 프롬프트 설계, 개인화 파이프라인
2. 시장 조사 — AI 타로 해석에 대한 사용자 기대와 경험담
3. 경쟁 분석 — 선행 AI 타로 서비스의 기능·모델·차별점

## Context

### 현재 코드베이스 상태

- **Chat feature**: `mobile/lib/features/chat/` — 플레이스홀더만 존재 (`ChatPage` "곧 추가됩니다")
- **Reading 도메인**: `Reading` 엔티티(deckId, spreadType, question, drawnCards), `DrawnCardInfo`(cardId, position, isReversed) — AI 해석의 입력 데이터 구조가 이미 존재
- **Card 데이터**: `TarotCard`(name, arcana, suit, number, meanings), `CardMeanings`(upright/reversed 키워드 리스트) — 카드별 기본 의미 데이터 보유
- **ReflectivePrompts**: 아케타입별 정적 반성 질문 22+4개 — 확증 편향 완화 목적으로 설계됨 (Arkes, 1991)
- **UserSettings**: experienceLevel(1~5), selectedDeckId, allowReversed 등 개인화 입력 존재
- **Server**: Rails 8+ 백엔드 구조 세팅됨 (PostgreSQL, 아직 API 미구현)
- **Shared**: OpenAPI 스키마 placeholder

### 기존 연구 자산

- **`docs/11_global_tarot_market/`**: 5개 권역 시장 조사 완료
  - "AI + 맥락 지속성"이 글로벌 차별화 요인으로 식별
  - "제의적 셀프 리딩 경험"이 미충족 니즈
  - 13개 에이전트 페르소나 + 7차원 평가 프레임워크 확정
  - 서비스 유형 택소노미 중 "AI 해석형" 카테고리 정의됨
- **`docs/01_성격서비스_기획/`**: 프로젝트 철학, 비즈니스 모델, 저작권 분석 완료
- **`docs/03_tarot_shuffle/`**: 셔플 엔진 기술 연구 62건 — 물리 셔플 → 카드 뽑기 흐름 완성

| 2 | 프롬프트 엔지니어링 전략 | 카드·덱·사조·유저 맥락을 결합하는 프롬프트 아키텍처 설계 방향 |

| 8 | 해석 품질 기준 | 바넘 효과 회피, 학술적 근거, 해석 깊이 vs 접근성 밸런스 기준 |

| 5 | LLM 선택 연구 범위 | **Claude + GPT 양대 API 비교 중심, 오픈소스 보조** | personality 프로젝트가 Claude Code 기반으로 개발 중이며 Anthropic API 친숙도가 높음. | 7 | 해석 사조 범위 | **RWS 표준 해석 기반 + 심리학적·상징학적·영적 관점 3가지 연구** | 현재 앱이 RWS(Rider-Waite-Smith) 덱 중심이며, `ReflectivePrompts`가 이미 심리학적 접근을 채택. 3가지 사조는 사용자 요청에 명시된 "다양한 해석 관점"에 부합하면서도 연구 범위를 관리 가능한 수준으로 제한 | 마르세유, 토트 등 비-RWS 덱의 해석 전통은 이번 연구에서 심화하지 않음 — 덱 확장 시 후속 연구 | 모든 해석 전통 — 연구 범위 비대; RWS만 — 사용자가 다양한 관점 요청 |
| 8 | 경쟁 분석 깊이 | **주요 5~8개 서비스 심층 분석 + 트렌드 파악** | 사용자가 "선행 서비스 기업들이 있는지 확인"을 명시적 요청. `docs/11_`에서 US 시장 AI 타로 33+개 식별됨 — 전수 조사는 비효율, 대표 서비스를 선별하여 기능·UX·비즈니스 모델·사용자 반응을 심층 분석하는 것이 인사이트 밀도 극대화 | 5~8개 선별 시 니치 서비스(특정 사조/문화 특화)를 놓칠 수 있음 — 트렌드 파악 과정에서 니치도 언급 | 전수 조사(33+개) — 깊이 부족; 3개만 — 비교 기반 빈약 |
