# 에뮬레이터 기반 페르소나 평가 — KR-01 × Personality 타로 앱 MVP

## 1. 평가 개요

### 1.1 목적

스펙 기반 평가(012)에서 코드 분석으로 파악한 기능 목록과, 에뮬레이터에서 실제 사용자가 경험하는 화면 간의 **갭(gap)**을 발견하고 점수를 보정한다.

### 1.2 방법론

| 항목 | 값 |
|------|-----|
| 평가 방법 | Android 에뮬레이터(emulator-5554) + ADB 스크린캡처 + UI Automator 덤프 |
| 디바이스 | 에뮬레이터 1080×2400 |
| 앱 버전 | Personality Tarot v0.1 |
| 페르소나 | KR-01 "불안한 취준생" (24세 여성, 이벤트+위안) |
| 시나리오 | "내일 면접인데 불안해서 타로 앱을 깔았다" |
| 비교 대상 | 스펙 기반 평가 012 (동일 페르소나, 동일 서비스) |

### 1.3 시나리오 플로우

```
Step 1: 앱 최초 실행 → 스플래시(Flutter 로고) → 홈 화면
Step 2: 홈 화면 첫인상 확인
Step 3: "바로 뽑기" 버튼 탭 → 카드 결과 화면
Step 4: 결과 화면 스크롤 → 해석/성찰 영역 확인
Step 5: 채팅 탭 → AI 해석 플레이스홀더 확인
Step 6: 저장소 탭 → 리딩 기록 확인
Step 7: 사용자 탭 → 유저메뉴/설정 확인
```

## 2. 화면별 상세 평가

### 2.1 Step 1~2: 앱 실행 → 홈 화면

**캡처 화면 설명**:
- Flutter 기본 스플래시(파란 Flutter 로고, 흰 배경) 약 3~4초 표시 후 홈 진입
- 홈 화면: 상단 로고("Personality Tarot" + 골드 심볼), 중앙 골드 원형 "바로 뽑기" 버튼, 하단 "최근 리딩" 목록
- 하단 네비게이션: 뽑기 / 저장소 / 채팅 / 사용자 (4탭)
- 로고 아래 칩: "즉시 · 1장 · Rider-Waite-Smith" (현재 설정 요약)

**KR-01 관점 평가**:

| 발견 | 평가 |
|------|------|
| 골드+다크 테마 | 고급스러운 느낌. 타로 앱다운 분위기. **긍정** |
| "Personality Tarot" 영어 브랜딩 | 한국 MZ세대 타깃인데 영어만? 점신/포스텔러는 한국어 브랜딩. **부정** |
| "바로 뽑기" 버튼 | 크고 직관적. CTA(Call-to-Action) 명확. **긍정** |
| "즉시 · 1장" 칩 | 현재 "즉시" 모드라는 건 알겠는데, 풀셔플이 있다는 건 모르겠음. **중립→부정** |
| 최근 리딩 목록 | 전부 "질문 없음" — 질문을 입력하는 곳이 있는지 모르겠음. **부정** |
| Flutter 기본 스플래시 | 브랜드 스플래시가 아닌 Flutter 로고 → "개발 중인 앱" 인상. **부정** |

### 2.2 Step 3: "바로 뽑기" → 카드 결과

**캡처 화면 설명**:
- "자유 선택 — 즉시" 헤더
- 상단에 "질문이 있으신가요? (선택)" 드롭다운 (접혀 있음)
- 중앙에 Ace of Pentacles 카드 이미지 (큼직, 고해상도)
- 카드 이름: "Ace of Pentacles" (영어)
- 하단 버튼 3개: "다시" / "+ 1장" / "리셋"
- **그 외 아무것도 없음** — 해석, 성찰 질문, 카드 의미 설명 전무

**KR-01 관점 평가**:

| 발견 | 평가 |
|------|------|
| 카드 이미지 품질 | RWS 표준 이미지, 크고 선명. **긍정** |
| 카드 이름이 영어 | "Ace of Pentacles"만 — 한국어 카드명("펜타클의 에이스") 없음. **부정** |
| **해석 콘텐츠 부재** | 카드를 뽑았는데 "그래서 이게 뭔데?"에 대한 답이 없음. **치명적 부정** |
| 성찰 질문 미노출 | 코드에 ReflectivePrompts가 존재하지만 이 화면에 표시되지 않음. **갭 발견** |
| "질문이 있으신가요?" 드롭다운 | 접혀 있고 "(선택)" 표시 → 대부분 무시할 것. 실제로 모든 기록이 "질문 없음". **발견성 문제** |
| "즉시" 모드 | 셔플 없이 카드가 바로 나옴. 의식(ritual) 경험 제로. 풀셔플 존재를 모름. **핵심 차별화 미노출** |
| "+1장" 버튼 | 카드 추가 뽑기 가능. 기능 자체는 좋으나 카드 간 관계/포지션 설명 없음. **중립** |

### 2.3 Step 4: 결과 화면 스크롤 시도

카드 이미지 아래로 **스크롤이 되지 않음**. 결과 화면 = 카드 이미지 + 이름 + 버튼 3개가 전부.

스펙 평가(012)에서 언급한 "성찰의 시간", "카드가 지금 당신에게 전하는 메시지" 등의 성찰 프롬프트가 **실제 화면에서는 보이지 않는다**. 이것이 스펙-실제 갭의 가장 큰 발견.

### 2.4 Step 5: 채팅 탭 → AI 해석

**캡처 화면 설명**:
- 전체 화면 다크 배경
- 중앙에 골드 말풍선 아이콘
- "AI 채팅"
- "타로 리딩에 대해 AI와 대화할 수 있는 기능이 곧 추가됩니다."
- 하단 네비게이션의 "채팅" 탭 활성화

**KR-01 관점**: 스펙 평가와 동일하게 완전 미구현 확인. 다만 실제 화면으로 보면 "곧 추가됩니다"라는 문구가 더 실망스럽게 느껴짐. 이 탭을 눌러본 시점은 이미 카드를 뽑고 해석이 없어서 찾아온 것이므로, "없다"는 답이 주는 좌절감이 스펙 분석보다 크게 체감됨.

### 2.5 Step 6: 저장소 탭 → 리딩 기록

**캡처 화면 설명**:
- "리딩 기록" 헤더
- 필터 칩: 전체 / 한 장 뽑기 / 쓰리 카드 / 자유 선택
- 리딩 목록: 날짜, 스프레드 유형, 카드 수 표시
- **모든 항목이 "질문 없음"**

**KR-01 관점**: 필터 기능은 깔끔. 하지만 모든 리딩이 "질문 없음"이라는 것은 질문 입력 UX가 실패했다는 증거. 리딩을 탭하면 과거 카드를 다시 볼 수 있을 것 같은데, 카드 해석이 없으므로 다시 봐도 의미가 없음.

### 2.6 Step 7: 사용자 탭 → 유저메뉴

**캡처 화면 설명**:
- "유저메뉴" 헤더
- 프로필 아이콘 + "탐험가" + "레벨 1 (즉시)"
- 메뉴 3개: 설정 / 덱 관리 / 앱 정보
- 앱 정보: "Personality Tarot v0.1"

**KR-01 관점**:

| 발견 | 평가 |
|------|------|
| "탐험가 레벨 1" | 게이미피케이션 요소? 맥락 설명 없이 레벨명만 → 의미 불명. **중립→부정** |
| "레벨 1 (즉시)" | 체험 레벨이 "즉시"라는 걸 여기서 알 수 있지만, 변경하려면 설정 진입 필요. **발견성 문제** |
| "v0.1" | 버전 넘버가 "0.1" → 알파/베타도 아닌 초기 개발 중 인상. **부정** |
| 설정/덱 관리 분리 | 깔끔한 구조. **긍정** |

## 3. 차원별 점수 — 에뮬레이터 보정

### D1. UX/의식 경험 (20%) — 3점 (스펙 4 → 에뮬 3, **-1**)

**스펙 평가에서의 가정**: "Flame 물리엔진 풀셔플이 독보적. 의도 설정→셔플→뽑기→성찰 플로우 완성도 높음."

**에뮬레이터 현실**:
- 기본 체험 레벨이 "즉시(레벨 1)" → 풀셔플(레벨 3)은 설정을 직접 바꿔야 접근 가능
- 첫 사용자는 "바로 뽑기" → 카드가 즉시 나옴 → "그냥 카드 보여주는 앱" 인상
- 의도 설정 화면이 별도로 존재하지 않고 "질문이 있으신가요? (선택)" 드롭다운으로 접혀 있음
- 결과 화면에 의식적 무게감(성찰 질문, 카드 해설) 없이 이미지만 표시
- 셔플 경험의 핵심 차별화가 **기본 플로우에서 빠져 있음**

**보정 근거**: 풀셔플 자체는 코드상 잘 구현되어 있으나, 첫 사용자가 도달할 수 없는 기능은 "없는 것과 같다". UX/의식 경험의 평가는 "기능 존재"가 아닌 "사용자 도달 가능성"으로 판단해야 함.

### D2. AI 해석 품질 (25%) — 1점 (변동 없음)

에뮬레이터에서 채팅 탭 확인 → "곧 추가됩니다" 플레이스홀더 그대로. 스펙 평가 정확.

다만 에뮬레이터에서 실제로 카드를 뽑고 → 해석 없음을 경험하고 → 채팅 탭을 눌러서 → "곧 추가됩니다"를 보는 **연속적 좌절 경험**은 스펙 분석에서 느낄 수 없는 감정적 임팩트. 1점은 동일하지만, 이 차원이 사용자 이탈의 직접 원인이라는 확신이 강화됨.

### D3. 콘텐츠 깊이 (5%) — 2점 (스펙 3 → 에뮬 2, **-1**)

**스펙 평가에서의 가정**: "RWS+홀리츠카 2덱, 기본 3스프레드 구비. 성찰 질문 존재."

**에뮬레이터 현실**:
- 카드 뽑기 결과 화면에 **카드 이미지와 영어 이름만 표시**
- 카드 의미 해설 없음, 성찰 질문 없음, 포지션 설명 없음
- 코드에 존재하는 ReflectivePrompts가 **UI에 미노출** — 스펙과 실제의 갭
- 카드 이름이 영어만 ("Ace of Pentacles") — 한국어 카드명 미지원
- 스프레드 선택은 설정에서 가능하나, 결과 화면에서 포지션별 의미 구분 없음

**보정 근거**: 코드에 데이터가 있어도 화면에 보이지 않으면 사용자에게는 "없는 것". 3점(평균)에서 2점(미달)으로 하향.

### D4. 문화적 적합성 (15%) — 3점 (변동 없음)

한국어 UI는 자연스러움 확인. "뽑기", "저장소", "유저메뉴", "리딩 기록" 등 용어 적절. 다만:
- "Personality Tarot" 영어 브랜딩
- 카드 이름 영어 전용 ("Ace of Pentacles")
- "탐험가" 레벨명 — 타로 맥락과 연결 불명확

스펙 평가에서 이미 이 점들을 반영했으므로 3점 유지.

### D5. 개인화/맥락 지속 (10%) — 2점 (변동 없음)

저장소에서 리딩 기록 확인 — 필터(전체/한 장/쓰리 카드/자유 선택) 작동. 하지만:
- **모든 리딩이 "질문 없음"** → 질문 입력 기능의 발견성 실패
- 사용자 프로필(유저메뉴)에 "탐험가 레벨 1" 외 개인 정보 없음
- 세션 간 연결 없음 — 각 리딩이 독립적

스펙 평가 2점과 동일하나, "질문 없음" 패턴이 반복되는 것을 시각적으로 확인하여 확신 강화.

### D6. 가격 가치 (15%) — 4점 (변동 없음)

완전 무료, 기능 제한 없음, 광고 없음. 에뮬레이터에서도 결제/광고 요소 일절 없음 확인.

### D7. 신뢰/프라이버시 (10%) — 3점 (스펙 4 → 에뮬 3, **-1**)

**스펙 평가에서의 가정**: "100% 로컬 데이터, 안전 고지, 위기상담 안내."

**에뮬레이터 현실**:
- 로컬 데이터 구조는 스펙대로 — 서버 통신 없음 확인 (긍정)
- 그러나 **실제 화면에서 안전 고지와 위기상담 안내를 발견하지 못함** — 코드에 존재하지만 어디에 표시되는지 불분명
- "Personality Tarot v0.1" → 알파 단계 앱 인상
- Flutter 기본 스플래시 → 브랜드 신뢰감 부재
- 이용약관, 개인정보처리방침 링크 없음 (유저메뉴의 "앱 정보"에서도 미확인)

**보정 근거**: 로컬 데이터 장점은 유지하나, 시각적 신뢰감 요소(브랜드 스플래시, 안전 고지 노출, 이용약관)가 에뮬레이터에서 확인되지 않아 -1.

## 5. 스펙-에뮬레이터 갭 분석

### 5.1 갭 유형 분류

## 7. 방법론 비교 — 스펙 vs 에뮬레이터 평가

### 7.1 각 방법의 강점/한계

| 차원 | 스펙 기반 | 에뮬레이터 기반 |
|------|----------|--------------|
| **속도** | 빠름 (코드 읽기) | 느림 (캡처+분석) |
| **기능 존재 확인** | 정확 (코드가 진실) | 부정확할 수 있음 (숨겨진 기능 미발견) |
| **사용자 경험 파악** | 부정확 (추론) | **정확** (실제 화면) |
| **발견성 평가** | 불가능 | **가능** |
| **감정적 임팩트** | 추론만 | 시각적으로 체감 |
| **D1 UX 평가** | 과대평가 경향 | 정확 |
| **D2 AI 평가** | 정확 (유무 판단) | 동일 |
| **D3 콘텐츠** | 과대평가 경향 | 정확 |
| **D6 가격** | 정확 | 동일 |
| **D7 신뢰** | 과대평가 경향 | 정확 |

### 7.2 권고 평가 프로세스

```
Phase 1: 스펙 기반 평가 (빠른 전체 점검)
  → 기능 유무, 데이터 모델, 아키텍처 수준 평가
  → D2(AI 해석), D6(가격) 같은 이진적 차원은 여기서 확정

Phase 2: 에뮬레이터 기반 보정 (UX 갭 발견)
  → D1(UX), D3(콘텐츠), D7(신뢰) 같은 체감 차원은 반드시 보정
  → 발견성 갭, 노출 갭, 인상 갭 식별

Phase 3: 교차 비교
  → 스펙-에뮬 갭 분석 → Quick Win 도출
```

이 2단계 접근이 단독 방법보다 정확하고 실행 가능한 인사이트를 산출한다.

## 9. 결론

이번 에뮬레이터 기반 평가의 가장 큰 수확은 **"기능이 있다 ≠ 사용자가 경험한다"**는 명제의 구체적 증거를 확보한 것이다.

풀셔플 물리엔진, 성찰 질문, 안전 고지 — 모두 코드에 잘 구현되어 있지만, 사용자의 기본 플로우에서 빠져 있다. 이 갭을 메우는 Quick Win 3건은 코드 변경량이 최소(설정 기본값 변경, UI 렌더링 추가, 플로우 재배치)이면서 점수 개선 효과가 가장 크다.

**AI 해석 구현 전에 Quick Win부터 적용하는 것을 권고한다.** 이유: AI 해석이 나와도 기본 플로우가 "즉시 뽑기 → 카드 이미지만"이면, 셔플 경험(D1)과 질문 맥락(D5)이 빠진 상태에서 AI만 덧붙이는 꼴이 된다. 풀셔플 기본화 + 질문 필수화 + 성찰 질문 노출이 AI 해석의 효과를 극대화하는 선행 조건이다.
