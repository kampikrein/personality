## 7. 구현 순서

| 단계 | 작업 | 산출물 | 의존성 |
|------|------|--------|--------|
| 1 | `personas/` 디렉토리 생성 | 디렉토리 | 없음 |
| 2 | `_framework.md` 작성 | 1개 파일 | 009 섹션 4 |
| 3 | 13개 페르소나 파일 작성 | 13개 파일 | 009 섹션 3.2 + 003/004/005 각 권역 섹션 |
| 4 | `_index.md` 작성 | 1개 파일 | 단계 2~3 완료 후 |
| 5 | 검증 — 파일 수/구조/가중치 합산 확인 | 검증 결과 | 단계 4 완료 후 |

### 단계별 상세

**단계 2**: _framework.md
- 009 섹션 4.1 (차원 정의), 4.2 (가중치 매트릭스), 4.3 (점수 기준), 4.4 (산출물 구조) 그대로 구조화
- 페르소나-유형 매핑 테이블 포함

**단계 3**: 13개 페르소나 파일 (병렬 작성 가능)
- 각 파일에 4개 섹션: 프로필(009), 권역 레퍼런스(003/004/005), 가중치(009+섹션 5 매핑), 프롬프트
- 권역 레퍼런스는 각 소스 문서의 해당 권역 섹션에서 핵심 5~10줄만 추출/요약
- 평가 가중치 테이블의 "이 페르소나의 관점" 열은 프로필 데이터(동기, 불만, 중점)에서 도출

**단계 4**: _index.md
- 13개 파일 목록 테이블
- 평가 유형별 그룹핑
- Agent() 실행 가이드 (단일/일괄 평가 방법)
- 통합 산출물 구조

**단계 5**: 검증
- 파일 수 = 15개 (ls 확인)
- 각 파일 frontmatter의 persona_id, eval_type 정합성
- 각 파일 가중치 합계 = 100%
- 프롬프트 템플릿의 플레이스홀더가 모두 구체 값으로 대체되었는지

## 8. 제약 사항 확인

| 제약 | 처리 |
|------|------|
| 전체 한국어 | docs/ 규칙. 모든 파일 한국어로 작성 |
| 자기 완결적 | 각 페르소나 파일은 Agent()가 단독으로 Read하여 평가 실행 가능해야 함. _framework.md 참조 불필요 |
| 가중치 자체 포함 | _framework.md는 공통 참조용이고, 각 페르소나 파일에 해당 eval_type 가중치를 직접 기재 |
| YAML 산출물 | 009 섹션 4.4의 구조를 그대로 사용. 필드명 영어(score, weight 등), 값은 한국어 |
| 코드 변경 없음 | 순수 문서 작업. apps/, packages/ 등 수정 없음 |
