# 성격서비스 기획 종합 리서치 — 최종

## Research Overview

### Background & Motivation

personality 프로젝트는 "자기 이해와 타인 수용의 자유"를 철학으로, 법률 우선 접근의 독자적 성격 서비스를 구축 중이다. 2026년 2월부터 기획이 시작되어 6개 문서(시장비교, 법률분석 2편, 프로젝트 철학, MVP 설계, IP 검증 스코프)가 생산되었고, Rails 8.1.2 코드베이스(모델 15개, 서비스 19개, 컨트롤러 13개)와 5+1개 전문 에이전트 조직이 구현되었다.

이 리서치는 산재한 기획 문서, 비전 메모, 코드베이스를 **종합 점검**하여 갭과 다음 단계를 도출한다.

## 관점 1: 기존 기획 문서 종합 & 갭 분석

### 현황 분석

8개 문서(001-006 + memo.md + gemini deep research)는 "법률 우선 독자 성격 서비스"라는 방향에서 논리적으로 정합한 흐름을 형성한다:

| 문서 | 핵심 결론 |
|------|----------|
| 001 (MBTI 서비스 비교) | 16Personalities가 독자 문항+Big Five 기반으로 상표권 우회한 가장 성공적 사례. 국내 비공식 서비스는 신뢰성 낮음 |
| 002 (저작권 법적보호) | MBTI는 상표+저작권 강력 보호. 에니어그램 9유형 구조는 공공영역(Arica v. Palmer). 부정경쟁방지법이 추가 리스크 |
| 003 (저작권 비용) | 공식 MBTI 자격 100만원+. 16Personalities식 우회 시에도 독자 브랜드+이론 근거 필수 |
| 004 (프로젝트 철학) | "자기 이해, 타인 수용, 자유". 저작권 우회로 유입 → 고급 서비스 전환. 타로/사주 확장 |
| 005 (법률우선 MVP) | 독자 문항/척도/브랜드, 8주 로드맵, 구성요소 A-F. AI 서사/소셜/마켓플레이스는 비목표 |
| 006 (IP 검증 스코프) | 6개 미검증 항목 식별: Enneagram 상표, Arica v. Palmer 판례번호 등 |
| memo.md | 성격 포탈, 쇼츠 스와이프, 캐릭터 AI, 소셜 커뮤니티, 타로/갤럭시타로 앱 |

### 상세 발견사항

**문서 간 모순/보완**:
- 004의 "저작권 우회"와 005의 "독자 문항/척도" — 모순이 아닌 추상도 차이의 동일 전략. 단, "우회"라는 표현 수정 권고
- 005 MVP 비목표(AI 서사, 소셜, 마켓플레이스) vs memo.md 비전(캐릭터, 커뮤니티, 소셜) — 방향은 일치하나 중간 로드맵 완전 부재

**006 미검증 6개 항목**: 전부 미해결 상태. 특히 "Enneagram" 용어 상표 등록 여부와 최신 부정경쟁방지법 판례는 서비스 범위에 직접 영향.

**미다루어진 주제 10개**: 독자 성격 모델 설계, 문항 개발 프로세스, 수익 모델, 사용자 획득 전략, 데이터 아키텍처, 접근성/다국어, 윤리 가이드라인, 개인정보보호법 구체 준수, 타로/사주 법적 검토, 경쟁사 대응 시나리오.

**memo.md 비전 반영도**: 11개 항목 중 2개만 부분 반영, 2개 비목표로 제외, 7개 완전 미반영.

### 주의사항 및 위험

- 004의 "저작권 우회" 표현이 법적 감사 시 오해 유발 가능
- 006의 미검증 항목이 서비스 런칭의 법적 안전성을 위협

### 요약

기획 문서의 논리적 흐름은 건전하나, "독자 성격 모델", "수익 모델", "Phase 2/3 로드맵"이라는 세 가지 핵심 공백이 존재.

## 관점 2: 코드베이스 vs MVP 설계 정합성

### 현황 분석

005 Plan의 구성요소 A-F를 실제 코드베이스와 매핑한 결과, **전반적 정합성이 높다**.

| 구성요소 | 판정 | 요약 |
|---------|------|------|
| A. 문항 엔진 | **완료** | 4도메인(energy, decision_making, relationship, recovery), 버전관리, 리커트 1-5, 역채점, 품질 메트릭 |
| B. 점수 엔진 | **완료** | 5개 서비스 파이프라인: DomainCalculator→Normalizer→TypeClassifier→ReliabilityAdjuster→PolicyChecker |
| C. 프로필 컴포저 | **완료** | 강점/주의패턴/권장행동, 독자 네이밍(character_name_ko/en), ToneFilter 11개 규칙 |
| D. 인사이트 모듈 | **완료** | 5개 맥락(협업/갈등/학습/커리어/회복) + ExplanationBuilder("Based on your...") + ContextEngine |
| E. 컴플라이언스 | **부분** | 익명세션/동의/삭제/제한표현 구현. 동의 폼 파라미터 불일치(C-5 잔존), 보관 기간 정책 미구현 |
| F. 품질 운영 | **부분** | BotDetector/SpeedAnalyzer 완비. 대시보드 기초 수준, Quality→Alert 자동 연동 미완성 |

### 상세 발견사항

**핵심 파이프라인 완성**: 문항→점수→프로필→인사이트의 6단계 데이터 흐름이 완전히 구현되어 있고, `full_flow_spec.rb` E2E 테스트로 검증됨.

**법적 보호 4중 체계 작동**: RestrictedTerms(상표 차단) → ToneFilter(낙인 방지) → TextPolicyFilter(콘텐츠 필터) → PolicyChecker(정책 차단).

**교차검증 이슈 해소 현황**: 004 Synthesis의 8개 Critical 이슈 중 5개 해결, C-5(동의 폼)만 잔존. C-4(null 제약)는 현재 일관.

**TypeClassifier의 설계 긴장**: 내부적으로 ENFP 등 MBTI 16유형 코드 사용. `PersonalityType.VALID_CODES`가 MBTI 동일 구조. `character_name_ko/en`이 대외 명칭을 담당하여 기능적으로 우회하지만, 근본적 독자화가 필요.

**DB 스키마**: PII 논리적 분리(users vs anonymous_sessions), User 모델 encrypts :email 적용. 물리적 분리(별도 DB)는 미구현. 동의 이력 버전 관리, 삭제 요청 연쇄 삭제 구현 완료.

### 주의사항 및 위험

- ResultsController의 rescue 블록 내 redirect_to 패턴에 이중 렌더 위험
- 데이터 보관 기간 자동 만료 정책 미구현
- 응답 데이터(responses) 자체는 미암호화

### 요약

핵심 파이프라인 완성도 높음. 즉시 수정 필요: 동의 폼 C-5, ResultsController 에러 흐름, Quality→Alert 연동.

## 관점 3: 비즈니스 모델 & 수익화 전략

### 현황 분석

경쟁 서비스 8개의 수익 모델을 7개 카테고리로 분류:

| 카테고리 | 대표 서비스 | 이 프로젝트 적용 |
|---------|-----------|--------------|
| 프리미엄(Freemium) | 16Personalities, Truity | **핵심 수익 엔진** |
| 광고 | 테스트모아, 테스트하로 | Phase 1 보조 수익 |
| 유료 리포트 | Truity, 16Personalities | Phase 2 핵심 |
| B2B/기관 | 한국MBTI심리연구소 | Phase 4 |
| 구독 | 16Personalities | Phase 3 |
| 데이터 수익화 | 푸망 | **미채택** (철학 충돌) |

### 상세 발견사항

**3대 수익 축**:
1. **고급 성격 서비스 (Core)**: 심층 프로필 리포트 9,900원, 호환성 리포트 6,900원
2. **커뮤니티/소셜 (Growth Engine)**: 월간 구독 4,900원, AI 캐릭터 2,900원/월
3. **타로/운명 서비스 (Revenue Diversifier)**: 1회 리딩 3,900원, 월간 구독 3,900원

**4단계 수익화 로드맵**:

| Phase | 기간 | 핵심 | 예상 월 수익 |
|-------|------|------|-----------|
| 1: 무료 유입 | 0-3M | MAU 1만 확보, 완전 무료 | ~50만 (광고) |
| 2: 프리미엄 전환 | 4-9M | 전환율 3%, 리포트/타로 판매 | ~100만+ |
| 3: 구독 + 커뮤니티 | 10-18M | MRR 구축, 네트워크 효과 | ~500만+ |
| 4: B2B + 플랫폼 | 19M+ | 기업 솔루션, API | ~1,000만+ |

**KPI 5계층 프레임워크**:
- Tier 1 (신뢰/법무): 정책 위반 0, 삭제 SLA >= 95%
- Tier 2 (제품 품질): 완료율 >= 70%, 이탈률 <= 30%
- Tier 3 (성장): MAU, 재방문 >= 20%, K-factor >= 0.3
- Tier 4 (수익화): CVR >= 3%, ARPU, MRR
- Tier 5 (단위 경제학): CAC <= 5,000원, LTV >= 30,000원, LTV/CAC >= 3:1

**JTBD 도출**: 사용자의 진정한 JTBD는 "나를 설명하는 언어를 얻고 싶다", "관계의 마찰을 이해하고 싶다", "불확실한 미래의 심리적 안전감".

**블루오션 ERRC**: 제거(MBTI 상표 의존, 1회성 이탈), 감소(문항 수 부담, 라벨 의존), 증가(행동 가이드, 심리학 근거 투명 공개), 창조(성격+운명 융합, AI 페르소나 대화, 성격 기반 커뮤니티, 진화하는 프로필).

### 주의사항 및 위험

- 독자 브랜드의 신뢰 구축 실패 시 전환율 1% 미만 위험
- 국내 MZ세대 지불 의향이 글로벌 대비 현저히 낮아 볼륨 전략 필수
- 데이터 수익화는 프로젝트 철학과 충돌하므로 미채택

### 요약

국내 성격 검사 시장에 "프리미엄 리포트 + 구독" 모델의 공백 존재. 타로/운명 통합이 블루오션 핵심. 신뢰 구축이 전환율 3%의 절대 전제.

## 관점 4: 사용자 여정 & 리텐션 전략

### 현황 분석

기존 성격 서비스의 핵심 문제: "검사 한 번 → 유형 라벨 → 이탈"의 일회성 소비 패턴.

### 상세 발견사항

**사용자 여정 재설계**:

```
As-Is: [유입] → [검사] → [결과] → [이탈] (1회성, 체류 15분)
To-Be: [유입] → [검사] → [프로필] → [인사이트 피드] → [캐릭터] → [타로] → [커뮤니티] → [재검사]
                                         ↑_____________________리텐션 루프____________________↓
```

**5개 세그먼트별 여정**: 호기심 탐색자, 자기성장 추구자, 관계 고민자, 운명/영성 탐구자, 전문 활용자(HR/코치).

**리텐션 레버 8개** (우선순위 순):

| 레버 | 구현 난이도 | 예상 리텐션 기여 | 우선순위 |
|-----|-----------|---------------|---------|
| 일일 인사이트 피드 ("성격 쇼츠") | 중간 | +15-20%p | P0 |
| 성장 트래킹/재검사 (90일 주기) | 낮음 | +5-10%p | P0 |
| 알림/푸시 전략 | 낮음 | +10-15%p | P0 |
| 성격 매칭 (유사/보완) | 중간 | +8-12%p | P1 |
| 캐릭터 대화 (매크로) | 중간-높음 | +12-18%p | P1 |
| 타로 통합 | 중간 | +10-15%p | P1 |
| 커뮤니티 | 높음 | +10-20%p | P2 |
| AI 에이전트 캐릭터 | 매우 높음 | +15-25%p | P3 |

**캐릭터 시스템**:
- Phase 1 (매크로): 메인 캐릭터 "나래" + 서브캐릭터 4명(하모/리커/패스/미스티). 의사결정 트리 + 문구 뱅크 30-50개. score_vector·방문횟수·시간대로 분기.
- Phase 2 (AI): LLM + 성격 도메인 지식. 사용자별 장기 기억. character.ai 대비 차별점: 심리학 근거 + 검사 데이터 기반 개인화.

**타로/운명 통합**:
- 성격검사보다 진입장벽 낮음 (설문 없이 카드 한 장)
- score_vector × 타로 카드 = 개인화 교차 해석 (기존 시장에 없는 독자적 가치)
- "타로로 유입 → 성격검사로 전환" 크로스셀 퍼널
- 갤럭시 타로 스타일 3D 셔플 UX

**커뮤니티 전환 전제**: MAU 10K+, 7일 리텐션 25%+, 평균 체류 5분+. 익명 반응("나도 그래요")부터 시작해 유형 그룹 → 소셜 커뮤니티 점진 전환.

## Cross-Analysis

### 관점 간 관계

**공통 발견 (4개 관점이 독립적으로 도달)**:
1. "독자 성격 모델"이 전체 전략의 미싱 피스 — 코드는 완성인데 측정 대상이 미정의
2. MVP-비전 사이 Phase 2/3 로드맵 부재 — 관점 3, 4가 독립적으로 거의 동일한 로드맵 설계
3. 신뢰 구축이 모든 전략의 선행 조건 — 법률(관점1) + 기술(관점2) + 수익(관점3)
4. 타로/운명 서비스의 삼중 가치 — 유입(관점4) + 수익(관점3) + 미기획(관점1)

**시너지**:
- ContextEngine(관점2) + 쇼츠 피드(관점4) = 적은 수정으로 리텐션 즉시 효과
- 법률 미검증(관점1) + 신뢰 = 전환(관점3) = 법률 검증이 곧 매출 전제
- 동의 폼 C-5(관점2) + 컴플라이언스 KPI(관점3) = 즉시 수정 필요

**긴장 포인트**:
- 내부 MBTI 코드 체계(관점2 "기능적 문제 없음") vs 독자화 필요성(관점1 "법적 오해 소지") → 독자화 권고, 비블로킹
- Phase 2 시점(관점3 "4-9M" vs 관점4 "6-12M") → 병행 가능: 리포트 4M, 캐릭터/타로 6M

### 공통 패턴

- 모든 관점이 "Phase 1에서 서두르지 말 것"을 강조 — 신뢰/데이터 축적 우선
- "독자 브랜드의 차별점 = 심리학적 깊이"가 반복적으로 등장
- 타로가 4개 관점 모두에서 전략적으로 중요하게 평가됨

### 갈등 항목

TypeClassifier의 MBTI 코드 사용에 대해: 관점 2는 "기능적 문제 없음, 리팩터링 선택적"으로 판단하고, 관점 1은 "법적 오해 소지"를 우려. 블루오션 관점(관점 4)의 "유형 라벨 명확성 감소" 전략과 결합하면, **내부 코드의 독자화가 장기적으로 옳은 방향**.

## Comprehensive Conclusion

### 핵심 발견 (우선순위 순)

1. **[Critical] R-013-F1: 독자 성격 모델 미설계** — 코드 파이프라인(A-F)은 완성이나 "무엇을 측정하는가"가 미정의. Big Five 기반? 독자 모델? 이론적 근거? 이 결정이 문항·리포트·신뢰·수익화를 모두 결정. *(관점 1, 2, 3)*

2. **[Critical] R-013-F2: 법률 검증 6개 항목 전부 미해결** — "Enneagram" 상표, Arica v. Palmer 판례번호(970 F.2d 1067 추정), MBTI 상표등록번호, KEPTI 저작권, 부정경쟁방지법 판례, 에이전트 레드라인 정합성. 서비스 범위와 마케팅 전략에 직접 영향. *(관점 1)*

3. **[High] R-013-F3: Phase 2/3 로드맵 공식화 필요** — 관점 3(수익화)과 관점 4(기능)가 독립적으로 거의 동일한 4단계 로드맵을 설계. 이를 공식 기획으로 통합하면 MVP-비전 간 공백 해소. *(관점 1, 3, 4)*

4. **[High] R-013-F4: 타로/운명 통합의 삼중 전략 가치** — 유입 채널(비고객 3계층) + 수익 다각화(저작권 이슈 없음) + 리텐션 레버(score_vector 교차 해석). 기획 문서에 공식화 시급. *(관점 3, 4)*

5. **[High] R-013-F5: 쇼츠형 인사이트 피드가 리텐션 핵심** — ContextEngine의 드립 모드 전환 + ExplanationBuilder 재활용으로 비교적 빠른 구현 가능. 7일 리텐션 +15-20%p 기대. *(관점 4)*

6. **[High] R-013-F6: 코드 파이프라인의 높은 완성도** — 005 Plan의 구성요소 A-D 완료, E-F 부분 구현. E2E 테스트 검증. 법적 보호 4중 체계 작동. 교차검증 8개 Critical 중 5개 해결. *(관점 2)*

7. **[Medium] R-013-F7: 내부 유형 코드의 MBTI 의존** — TypeClassifier/PersonalityType이 MBTI 동일 구조. character_name_ko/en으로 대외 우회하나 독자화 권고. *(관점 1, 2)*

8. **[Medium] R-013-F8: 운영 인프라 미완성** — Quality→Alert 자동 연동, 만족도/피드백 수집, 데이터 보관 기간 정책 미구현. *(관점 2)*
