# 글로벌 타로 앱 시장 조사 & 평가 에이전트 설계

## Intent

자사 타로 서비스(personality 프로젝트)의 글로벌 포지셔닝을 위해, 5개 주요 권역(한국/미국/일본/중국/EU)의 타로 앱 시장을 체계적으로 조사한다.

**최종 목표**: 조사 결과를 기반으로 각 권역·유형·이용 스타일을 대표하는 "고객 에이전트" 페르소나를 구축하고, 이 에이전트들이 자사 서비스를 다각적으로 평가하는 시뮬레이션 프레임워크를 만든다.

**단계적 구조**:
1. 시장 조사 (데이터 수집 & 분석)
2. 에이전트 페르소나 설계 (권역별 대표 특성 모델링)
3. 평가 프레임워크 구축 (에이전트 기반 서비스 평가 시뮬레이션)

## Decisions

| # | Decision | Chosen | Rationale | Trade-off | Alternatives Considered |
|---|----------|--------|-----------|-----------|------------------------|
| 1 | 조사 범위: 5개 권역 | KR/US/JP/CN/EU | 타로 문화의 근원(EU), 최대 시장(US/CN), 문화적 유사성(JP), 자사 1차 시장(KR) — 글로벌 타로 앱 시장의 주요 축을 모두 포괄. 동남아/중남미 등은 시장 규모와 데이터 접근성 대비 우선순위가 낮음 | 동남아(태국 등) 타로 문화가 강하나 앱 시장 데이터가 제한적. 인도/중동도 점술 문화가 있으나 타로 특화 앱 시장이 미성숙 | 7개 권역(+동남아, 인도) — 데이터 수집 비용 대비 인사이트 한계로 기각; 3개 권역(US/KR/JP) — 서구 근원(EU)과 최대 신규 시장(CN)을 놓침 |
| 2 | 조사 방법론 | 공개 데이터 기반 데스크 리서치 | App Store/Google Play 랭킹, 리뷰 데이터, 앱 분석 사이트(Sensor Tower, data.ai 공개 정보), 미디어 기사, 학술 자료 활용. 실제 앱 다운로드·체험은 주요 앱에 한정 | 1차 사용자 설문이나 인터뷰 없이 2차 자료에 의존하므로 사용자 심층 동기 파악에 한계 | 사용자 설문 포함 — 시간/비용 과다로 기각; 앱 다운로드 전수 체험 — 물리적 한계로 기각 |
| 3 | 에이전트 설계 접근 | 레퍼런스 주입형 페르소나 | 수집된 시장 데이터를 에이전트 컨텍스트로 주입하여 "경험 기반" 페르소나 구축. 단순 프롬프트 페르소나가 아닌, 실제 데이터가 뒷받침하는 구조 | 데이터 품질에 페르소나 정확도가 의존 — 데이터가 편향되면 에이전트도 편향 | 프롬프트만으로 페르소나 — 구체성 부족으로 기각; 실제 사용자 인터뷰 기반 — 비용 과다로 기각 |
| 4 | 에이전트 페르소나 축 | 3축 구조 (권역 x 유형 x 스타일) | **권역**(문화·규제·시장), **서비스 유형 선호**(AI 해석/셀프 리딩/라이브 등), **이용 스타일**(일상 습관형/이벤트형/학습형 등) — 3축 교차로 다차원 평가 가능 | 축이 3개면 조합이 많아질 수 있음 — 대표 조합만 선별하여 관리 | 2축(권역 x 유형) — 이용 스타일 차이를 놓침; 4축(+연령대) — 데이터 확보 어려움으로 기각 |
| 5 | 에이전트 페르소나 수 | 권역당 2~3개 (총 10~15개) | 초기 프레임워크 검증 단계에서는 대표성 있는 소수가 효율적. 3축(권역 x 유형 x 스타일) 전체 조합(5×3×3=45)을 만드는 건 무의미 — 조사 과정에서 실제 데이터가 보여주는 "이 권역에서 지배적인 조합"만 선별. 이후 평가 결과에 따라 세분화 확장 가능 | 권역 내 소수 유형만 대표하므로 니치 사용자 관점 누락 가능 | 권역당 4~5개(총 20~25개) — 조사·관리 비용이 프레임워크 검증 가치를 초과; 권역당 1개 — 권역 내 다양성 무시 |
| 6 | 평가 대상 범위 | 경쟁사 포함 비교 평가 | 에이전트가 "이 시장에서 다른 앱을 써본 사용자" 역할을 하려면 경쟁 서비스 경험 데이터가 필수. 자사 서비스만 평가하면 절대 점수만 나오고 상대적 포지셔닝 판단 불가. 조사 Phase 1에서 이미 경쟁 앱 데이터를 수집하므로 추가 비용 최소 | 경쟁사 상세 정보(내부 기능 흐름 등) 접근에 한계 — 공개 정보(스토어 스크린샷, 리뷰, 기사) 범위 내로 제한 | 자사만 평가 — 상대 위치 파악 불가로 기각 |
| 7 | 활용 시점 | MVP 방향성 즉시 반영 + 글로벌 준비 병행 | 현재 MVP가 "한국 시장 전용"으로 고착되기 전에 글로벌 호환성을 점검하는 것이 수정 비용 최소. 조사 결과 중 즉시 반영 가능한 인사이트(UX 패턴, 콘텐츠 구조)는 MVP에 피드백하고, 권역별 현지화 전략은 중장기 참고자료로 축적 | 조사 범위가 넓어져 단기 집중도가 분산될 수 있음 — 조사는 병렬(에이전트 위임)이므로 현재 개발 흐름에 영향 최소화 | 글로벌 확장 시점까지 보류 — MVP가 한국 전용으로 고착된 후 수정 비용 증가; MVP 전면 반영 — 현재 개발 속도 저하 |

## Constraints

- **데이터 접근성**: 중국 시장은 Google Play 미운영, iOS App Store 중국 랭킹과 바이두/위챗 미니프로그램 등 별도 채널 조사 필요
- **언어 장벽**: 일본어/중국어 리뷰·기사의 정확한 해석 필요 (웹 검색 기반)
- **시장 데이터 시의성**: 앱 마켓 데이터는 빠르게 변동 — 조사 시점 명시 필수
- **LLM 지식 한계**: 2025년 5월 기준 학습 데이터 — 최신 앱/트렌드는 웹 검색으로 보완

## Exit Criteria

1. 5개 권역별 수요·공급·주요 서비스·유형 분류가 구조화되어 있을 것
2. 에이전트 페르소나 구조(축, 속성, 레퍼런스 주입 방식)가 정의되어 있을 것
3. 평가 프레임워크의 차원·기준·방법이 정의되어 있을 것
4. 조사 실행 계획(단계, 데이터 소스, 산출물 형식)이 수립되어 있을 것

## Model Anchors

- **조사 권역**: KR, US, JP, CN, EU — 5개 고정. 추가 권역 없음.
- **조사 방법**: 공개 데이터 기반 데스크 리서치. 웹 검색, 앱스토어 공개 정보, 미디어/학술 자료.
- **에이전트 설계**: 3축(권역 x 서비스유형선호 x 이용스타일). 각 에이전트에 조사 데이터를 레퍼런스로 주입.
- **산출물 위치**: `docs/11_global_tarot_market/` 하위.
- **문서 언어**: 한국어 (docs/ 규칙 준수).
- **연구 자세**: `/research` 스킬 활용 가능한 구조로 설계. 각 권역 또는 주제를 병렬 조사 가능하도록 모듈화.
- **페르소나 수**: 권역당 2~3개, 총 10~15개. 3축 전체 조합이 아닌 데이터 기반 지배적 조합만 선별.
- **평가 대상**: 자사 + 경쟁사 비교 평가. 경쟁사 데이터는 공개 정보(스토어, 리뷰, 기사) 범위 내.
- **활용 시점**: 즉시 반영 병행. UX/콘텐츠 인사이트는 MVP 피드백, 현지화 전략은 중장기 축적.
