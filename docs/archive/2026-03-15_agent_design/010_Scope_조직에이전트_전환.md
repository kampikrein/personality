# Claude Code 에이전트의 조직 에이전트 전환

## 작업 목표

현재 5개 전문 에이전트가 **독립적으로** 작동하는 구조를 **조직적 협업 시스템**으로 전환한다.

**현재 상태 (As-Is)**:
- 5개 에이전트: psychology-expert, mbti-expert, enneagram-expert, coding-expert, uiux-expert
- 각 에이전트는 독립 실행, 사용자가 수동으로 중재
- 에이전트 간 소통 프로토콜/SOP 없음
- 기억 체계는 개별 에이전트별 yaml 파일로 격리

**목표 상태 (To-Be)**:
- 오케스트레이터 에이전트가 작업 분배·품질 관리 수행
- 에이전트 간 구조화된 인계 포맷으로 환각 캐스케이딩 방지
- 워크플로우별 SOP 패턴 정의 (파이프라인, 비판 루프, 병렬 탐색)
- 조직 수준 기억 공유 체계

**성공 기준**:
- 사용자가 오케스트레이터에게 단일 지시를 내리면 적절한 에이전트 조합이 자동 활성화
- 에이전트 간 인계 시 정보 손실·환각 증폭 없음
- 각 에이전트의 산출물이 표준화된 포맷을 따름

**제약 조건**:
- Claude Code의 `.claude/agents/*.md` 프레임워크 안에서 구현
- 별도 런타임 시스템(Python MAS 등) 미도입
- 기존 에이전트 기억 데이터 보존

## 접근 방향

doc 002에서 제시한 5가지 MAS 구조 중, 이 프로젝트에 적합한 **하이브리드 구조** 채택:

1. **계층형 (Hierarchical)** — 오케스트레이터가 작업 분해·위임 담당
2. **순차 파이프라인 (Sequential)** — 표준 개발 워크플로우 (요구사항→설계→구현→검증)
3. **평가/정제 루프 (Critique Loop)** — 도메인 전문가의 교차 검증

병렬/디스패처는 Claude Code 에이전트의 동시 실행 제약으로 현 단계에서 제외.
그룹 채팅은 토큰 비용 폭증 위험으로 제외.

### /clear 후 복원 방법
- Scope 문서 → 작업 목표, 사이클 순서, 영역 정보
- Research/Plan 문서 → 각 사이클의 조사 결과, 구현 계획
- 다음 스킬이 이전 문서를 자동 참조하므로 연속성 유지
