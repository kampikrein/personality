# 에이전트 조직화: 개별 전문가 → 조직 에이전트 시스템 전환

## 작업 목표

현재 5개 독립 Claude Code 에이전트를 **조직 에이전트 시스템**으로 전환한다.

### 핵심 목표
1. 사용자가 모든 에이전트 간 조정을 직접 하는 현재 구조 → 오케스트레이터가 자동 조정
2. 자유 텍스트 기반 소통 → 구조화된 인계 포맷과 SOP 프로토콜
3. 피상적 페르소나(Role + Principles) → 5요소 명세 체계(Role/Goal/Backstory/Tools+Guardrails/Memory)

### 제약 조건
- Claude Code 에이전트 프레임워크(.claude/agents/*.md) 내에서 구현
- 기존 에이전트의 도메인 지식과 기억 체계 보존
- 프로젝트 핵심 가치(자기이해, 상호수용, 자유) 준수

### 성공 기준
- 오케스트레이터를 통해 복합 작업(예: "새 문항 세트 추가")을 에이전트 팀이 분업 처리
- 에이전트 간 산출물 인계 시 구조화된 포맷 사용
- 교차 검증 루프가 자동으로 작동 (예: coding → psychology 학술 검증)

## 접근 방향

### 선택: 계층형 + 평가/정제 루프 하이브리드 (Claude Code 내 구현)

**근거**:
- 성격 서비스의 SDLC가 명확한 단계적 구조를 가짐 → 계층형 적합
- 학술 검증/법적 검증이 필수 → 평가/정제 루프 필수
- Claude Code 에이전트는 순차 호출 구조 → 병렬/그룹채팅 부적합
- 즉시 실행 가능 + 기존 자산 보존 → 런타임 MAS 도입보다 현실적

**기각된 대안**:
- 런타임 MAS(LangGraph/CrewAI): 별도 Python 프로젝트 필요, 현 단계에서 과도
- 협력적 그룹 채팅: Claude Code 동시 실행 불가, 토큰 비용 과도
- 순수 파이프라인: 유연성 부족, 예외 상황 대처 어려움
