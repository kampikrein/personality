## Summary

8개 문서는 "법률 우선 독자 성격 서비스" 구축이라는 핵심 방향에서 대체로 일관된 논리를 형성한다. 001(경쟁 분석) -> 002(법적 보호 체계 이해) -> 003(비용 현실 확인) -> 004(철학 수립) -> 005(MVP 설계)로 이어지는 기획 흐름은 논리적으로 정합하다. 그러나 memo.md의 비전(캐릭터, 커뮤니티, 소셜, 타로/사주 확장)은 005의 MVP 범위와 시간 축에서 연결 고리가 부재하며, 006에서 제기한 6개 미검증 항목은 모두 미해결 상태로 서비스 런칭 전 반드시 해소해야 한다.

### 2. 문서 간 모순/일관성 분석

#### 2-1. 004 "저작권 우회" vs 005 "독자적 문항/척도/브랜드" -- 보완 관계

**결론: 모순이 아니라 추상도가 다른 동일 전략의 두 표현이다.**

- 004는 "저작권 우회 방식을 사용하여 법적 리스크 최소화"라고 선언적으로 기술한다.
- 005는 이를 구체화하여 "공식 MBTI/애니어그램 검사 문항, 보고서 문구, 보호된 브랜드 표현을 사용하지 않음 / 독자적인 문항 뱅크, 독자적인 척도 라벨, 독자적인 보고서 문구 사용"으로 명시한다.
- 004의 "우회"라는 표현이 자칫 기존 도구를 모방하되 법적 추적만 피하려는 뉘앙스를 줄 수 있어, 005의 "독자 창작" 접근과 인식 차이가 생길 수 있다. 그러나 003에서 16Personalities의 사례를 분석하며 "독자 브랜드와 이론적 근거를 제시해야 법적 방어 가능"이라고 결론짓고 있어, 세 문서를 함께 읽으면 일관된 전략이 된다.
- **개선 권고**: 004의 "저작권 우회"라는 표현을 "독자적 도구 개발"로 수정하면 오해를 방지할 수 있다.

#### 2-2. 005 "비목표(MVP)" vs memo.md 비전 -- 타임라인 정합성 부재

**결론: 방향은 모순되지 않으나, 중간 단계의 로드맵이 완전히 누락되어 있다.**

- 005의 비목표: "AI 생성 진단 서사 없음 / 소셜 피드·바이럴 공유 없음 / 복잡한 추천 마켓플레이스 없음"
- memo.md의 비전: "캐릭터 AI 대화 / 소셜 커뮤니티 / 쇼츠 스와이프형 콘텐츠 / 커뮤니티 그룹"
- 005의 MVP(8주)에서 이 모든 것을 비목표로 선언하는 것 자체는 합리적이다. 그러나 MVP 이후 어떤 단계를 거쳐 memo.md의 비전에 도달하는지에 대한 **Phase 2/3 로드맵이 전혀 존재하지 않는다**.
- 특히 memo.md의 "캐릭터 AI 에이전트"와 "소셜 커뮤니티"는 기술 아키텍처, 데이터 모델, 비용 구조가 완전히 다른 제품이므로 단순 기능 추가가 아닌 재설계가 필요할 수 있다.
- **정합성 리스크**: MVP 아키텍처가 나중에 소셜/캐릭터 기능을 수용하지 못하면 기술 부채 발생.

#### 2-3. 001 경쟁 분석 결론 vs 005 설계 방향 -- 일치

**결론: 높은 일관성.**

- 001은 16Personalities가 독자 문항(Big Five 기반)+독자 척도(-A/-T 추가)+무료 기본 서비스+유료 리포트 모델로 성공했음을 분석하고, 국내 비공식 서비스들의 낮은 신뢰성을 지적한다.
- 005는 이 분석을 직접 반영하여: (1) 독자 문항 뱅크, (2) 독자 척도 라벨, (3) 프로필 벡터 기반 비고정 유형, (4) 신뢰·컴플라이언스 레이어, (5) 품질 운영 대시보드를 설계에 포함했다.
- 001의 권고 "비공식 검사의 신뢰도 한계"에 대응하여 005가 문항 품질 점검, 신뢰도 보정, 봇 탐지를 설계에 포함한 점이 적절하다.
- **보완 필요**: 001에서 분석한 "무료 테스트 -> 유료 리포트" 비즈니스 모델은 005에서 다루지 않는다(관점3 영역이지만 기술적 결제 인프라는 미리 고려 필요).

### 7. 001_gemini_deep_research 문서의 위치

이 문서는 성격 서비스 기획과 직접적 관련이 없는 일반 비즈니스 발굴 방법론 논문이다. 다만 다음 측면에서 간접적으로 연결된다:
- **JTBD 프레임워크**: memo.md의 "궁금증이 있는 사람들에게 가벼운것부터 무거운것까지 준비"라는 비전은 JTBD 관점에서 "자기 이해라는 Job을 수행하려는 사용자"로 재해석 가능
- **다중 에이전트 시스템**: 프로젝트가 실제로 다중 에이전트 아키텍처를 코드베이스에 구현하고 있음(git log 확인)
- **페르소나 디자인**: memo.md의 캐릭터 AI 에이전트 구상과 직접 연결

그러나 이 문서가 `docs/01_성격서비스_기획/` 폴더가 아닌 `docs/` 루트에 위치한 것은, 기획 문서 체계와 분리된 독립 참고자료임을 시사한다.

## Key Findings

1. **법적 전략의 일관성은 확보됨**: 002 -> 003 -> 004 -> 005로 이어지는 "독자 도구 개발" 전략은 논리적으로 일관된다. 다만 004의 "우회"라는 표현이 오해를 유발할 수 있다.

2. **006의 미검증 6개 항목이 모두 미해결**: 서비스 런칭의 법적 안전성을 위한 핵심 전제 조건들이 여전히 검증되지 않았다. 특히 "Enneagram" 용어 상표 등록 여부와 최신 부정경쟁방지법 판례는 즉시 확인해야 한다.

3. **MVP와 비전 사이의 거대한 공백**: 005의 8주 MVP와 memo.md의 "소셜 커뮤니티+캐릭터 AI" 비전 사이에 Phase 2/3 로드맵이 부재하다. MVP 아키텍처가 비전 수용 불가능한 구조로 구축될 리스크가 있다.

4. **독자 성격 모델이 미설계**: 005가 문항 엔진과 점수 엔진의 기술 구조를 상세히 설계했으나, 정작 "어떤 성격 모델을 사용하는가"라는 핵심 질문에 대한 답이 없다. Big Five 기반인지, 완전 독자 모델인지, 이론적 근거가 무엇인지 결정되지 않았다.

5. **수익 모델 공백**: 001에서 경쟁사 수익 모델을 상세히 분석했으나, 본 서비스의 수익 모델은 어떤 문서에도 구체화되지 않았다.

6. **문서 간 중복**: 002와 003의 부정경쟁방지법 서술, MBTI 상표권 서술이 상당 부분 중복된다. 이는 두 문서의 생산 맥락이 다르지만(002: 법적 체계 연구, 003: Gemini Q&A) 내용적 정리가 필요함을 시사한다.

## Recommendations

### 즉시 조치 (MVP 출시 전)
1. **006 미검증 항목 해소**: USPTO/KIPRIS에서 "Enneagram" 상표 검색, Arica v. Palmer 판례번호 확인(970 F.2d 1067 추정), MBTI 상표등록번호 확인을 실제로 수행할 것. 웹 검색이 가능한 에이전트 또는 인간 리서처에게 할당 필요.
2. **독자 성격 모델 문서 작성**: "어떤 이론에 기반하여, 어떤 도메인/척도로, 몇 개의 문항으로 측정하는가"를 정의하는 설계 문서가 MVP 개발 착수의 실질적 전제 조건.
3. **부정경쟁방지법 구체 판례 확보**: 003의 "경향" 서술을 넘어, 실제 유사 사례(성격검사 서비스 관련 또는 성과 무단 사용 관련) 판례 최소 2-3건 확보.

### 단기 조치 (MVP 설계 보완)
4. **Post-MVP 로드맵 작성**: MVP(8주) -> Phase 2(캐릭터/콘텐츠) -> Phase 3(소셜/커뮤니티)의 단계적 진화 계획. 특히 MVP 아키텍처가 Phase 2/3를 수용할 수 있도록 확장 포인트를 미리 설계.
5. **수익 모델 초안**: MVP 단계에서의 수익 전략(광고? 프리미엄 리포트? 완전 무료?)을 최소한 가설 수준으로 정의.
6. **004 용어 수정**: "저작권 우회"를 "독자적 도구 개발" 또는 "공공 영역 이론 기반 독자 구현"으로 수정하여 법적 오해 방지.

### 중기 조치
7. **타로/사주 확장 법적 검토**: 004가 언급한 확장 방향에 대한 별도 법적 리서치 문서 필요.
8. **윤리 가이드라인 구체화**: 005의 원칙적 선언("낙인 금지, 결정론적 주장 금지")을 구체적 가이드라인+심사 프로세스로 발전.
